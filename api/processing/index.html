Signal processing and impedance estimation.

BLTVA¶

bltva ¶

BLTVA — Band-Limited Time-Varying Analysis estimator.

Estimates the time-varying transfer function H(w,t) between an excitation signal and a response signal measured under (odd random phase) multisine excitation, following

Hallemans et al., Electrochim. Acta 466 (2023) 142939, eq. (71)-(81)
Hallemans et al., IEEE TIM 70 (2021) 6503814, eq. (55), (58), Algorithm 2
Breugelmans et al., Electrochim. Acta 76 (2012) 375, eq. (1)-(14)   [LTV-only variant]

Model, per excited bin k_e, over a local band K_w:

V(k) = sum_p     theta_p(k_e) B_p(k - k_e)          # target skirt
     + sum_{k'}  sum_p theta_p(k') B_p(k - k')      # other harmonics in band
     + sum_q     theta_q B_q(k)                     # drift skirt at DC
     + sum_r     alpha_r L_r(xi(k))                 # transients + out-of-band

H_p(w_ke) = theta_p(k_e) / U(k_e)
H(w_ke, t) = sum_p H_p(w_ke) b_p(t)

with the scaled DFT X(k) = (1/N) sum_n x(n) exp(-j2 pi k n / N) and Legendre basis b_p(t) = L_p(2t/T - 1).

Naming is deliberately excitation/response rather than current/voltage: in galvanostatic mode pass (excitation=i, response=v) and read the result as an impedance; in potentiostatic mode pass (excitation=v, response=i) and read it as an admittance.

Included: the band-limited least-squares estimate (TIM 2021 eq. 55-58), noise variance estimation (Algorithm 1), regressor selection (Algorithm 2), nonlinear distortion variances (Section V), uncertainty from both noise and distortion (Section VI), and trend removal by differencing (TIM 2022), via :mod:deistools.processing.detrending.

Distortion estimation needs harmonics="all_nl" and an excitation that leaves harmonics unexcited -- an odd random phase multisine. With harmonics="excited" there are no regressors away from the excited bins, so the distortion is unobservable and cov_H_p falls back to the noise term alone. The excitation must also carry uniformly random phases, which no inspection of the data can confirm; see the precondition note on :class:BLTVAResult.

Designing such an excitation is out of scope here -- this module takes H_exc as given, whatever produced it. The companion multisine package has Multisine.generate_orp for it, but nothing in DEIStools depends on that, by design: a user with their own waveform designer should not be shut out.

Still outstanding: the local band is narrower than eq. (55) prescribes; see _band_bins.

Dependencies: numpy, matplotlib.

Notes

Precondition on the distortion results. var_distortion_even, var_distortion_odd, cov_H_p_distortion and :meth:sndr_db are only meaningful for an odd random phase excitation. That means three things at once:

  1. only odd harmonics excited, so even-order distortion lands on empty even harmonics;
  2. some odd harmonics left unexcited, so odd-order distortion has somewhere to appear;
  3. phases drawn uniformly at random, which is what makes E{exp(j*phi)} = 0 and the best linear approximation well defined.

The first two are visible in H_exc and are enforced: a grid with no unexcited odd harmonic in band yields None and :meth:sndr_db raises. The third cannot be checked from a single record and is the caller's responsibility. Phases chosen for a low crest factor -- Schroeder, or a best-of-N random search -- violate it, and the distortion variances then come out wrong rather than absent, with nothing to indicate it. If you optimised the crest factor, do not read these attributes.

The drift is deliberately not reported. In Hallemans TIM 2021 theta_q is a nuisance parameter: eq. (58) carries the trend so that it does not bias theta_p(k_e), and eq. (68) extracts only G_p. Within a single band the trend's 1/k tail is nearly collinear with the transient polynomial, so theta_q is not individually identifiable there. An earlier version of this module returned it anyway, reconstructed from the lowest band alone, and it was wrong by ~50% of the drift range with a 26% imaginary part. Recovering the trend belongs to a detrending step, which knows what it removed.

class BLTVAResult:
    """Output of :func:`bltva`.

    Attributes
    ----------
    f_exc : (M,) float
        Excited frequencies in Hz.
    t : (N,) float
        Time axis in s.
    H_p : (M, Np+1) complex
        Basis coefficients of the transfer function at each excited frequency.
        ``H_p[:, 0]`` is the best stationary (time-averaged) transfer function.
    H_wt : (M, N) complex
        Time-varying transfer function, reconstructed on the full time axis.
    diagnostics : list of dict
        One entry per excited frequency: band width, unknowns before and after
        pruning, how many regressors each pruning step removed, the noise
        variance used as threshold, condition number, rank, relative residual.

    Notes
    -----
    **Precondition on the distortion results.** ``var_distortion_even``,
    ``var_distortion_odd``, ``cov_H_p_distortion`` and :meth:`sndr_db` are
    only meaningful for an odd random phase excitation. That means three
    things at once:

    1. only odd harmonics excited, so even-order distortion lands on empty
       even harmonics;
    2. some odd harmonics left unexcited, so odd-order distortion has
       somewhere to appear;
    3. phases drawn uniformly at random, which is what makes
       ``E{exp(j*phi)} = 0`` and the best linear approximation well defined.

    The first two are visible in ``H_exc`` and are enforced: a grid with no
    unexcited odd harmonic in band yields ``None`` and :meth:`sndr_db`
    raises. **The third cannot be checked from a single record and is the
    caller's responsibility.** Phases chosen for a low crest factor --
    Schroeder, or a best-of-N random search -- violate it, and the distortion
    variances then come out *wrong rather than absent*, with nothing to
    indicate it. If you optimised the crest factor, do not read these
    attributes.

    The drift is deliberately not reported. In Hallemans TIM 2021 ``theta_q``
    is a nuisance parameter: eq. (58) carries the trend so that it does not
    bias ``theta_p(k_e)``, and eq. (68) extracts only ``G_p``. Within a single
    band the trend's 1/k tail is nearly collinear with the transient
    polynomial, so ``theta_q`` is not individually identifiable there. An
    earlier version of this module returned it anyway, reconstructed from the
    lowest band alone, and it was wrong by ~50% of the drift range with a 26%
    imaginary part. Recovering the trend belongs to a detrending step, which
    knows what it removed.
    """

    f_exc: np.ndarray
    t: np.ndarray
    H_p: np.ndarray
    H_wt: np.ndarray
    cov_H_p_noise: np.ndarray | None = None
    cov_H_p_distortion: np.ndarray | None = None
    var_distortion_even: np.ndarray | None = None
    var_distortion_odd: np.ndarray | None = None
    response_power: np.ndarray | None = None
    diagnostics: list = field(default_factory=list)
    _basis: np.ndarray | None = field(default=None, repr=False)

    def worst_condition(self) -> float:
        return max(d["cond"] for d in self.diagnostics)

    def worst_residual(self) -> float:
        return max(d["rel_residual"] for d in self.diagnostics)

    @property
    def cov_H_p(self) -> np.ndarray:
        """Total covariance of ``H_p``, eq. (76): noise plus odd distortion.

        Falls back to the noise term alone when distortion was not estimated,
        i.e. when ``harmonics="excited"`` left no unexcited harmonic to read
        it from.
        """
        if self.cov_H_p_noise is None:
            raise ValueError(
                "no uncertainty available: bltva was called with prune=False "
                "and no noise estimate, so C_V is unknown")
        if self.cov_H_p_distortion is None:
            return self.cov_H_p_noise
        return self.cov_H_p_noise + self.cov_H_p_distortion

    @property
    def std_H_p(self) -> np.ndarray:
        """Total standard deviation of each ``H_p``, shape ``(M, Np+1)``."""
        diag = np.einsum("mpp->mp", self.cov_H_p).real
        return np.sqrt(np.maximum(diag, 0.0))

    def sndr_db(self) -> np.ndarray:
        """Signal-to-nonlinear-distortion ratio at each excited frequency, dB.

        ``|Y(k_e)|^2`` against the total distortion variance, which is what
        Section V says to compare in order to "decide whether the linear
        approximation of the system is acceptable". Large is good: the
        measurement examples in the paper report a minimum around 30 dB and
        treat a linear model as justified there.

        Requires an odd random phase excitation -- see the precondition on
        :attr:`var_distortion_odd`.
        """
        if self.var_distortion_odd is None:
            raise ValueError(
                'no distortion estimate: run with harmonics="all_nl" and an '
                "excitation that leaves harmonics unexcited")
        total = np.nansum(self.var_distortion_even, axis=1) + \
            np.nansum(self.var_distortion_odd, axis=1)
        with np.errstate(divide="ignore"):
            return 10.0 * np.log10(self.response_power / total)

    def variance_over_time(self, t_index=None) -> np.ndarray:
        """eq. (87): sigma^2(jw_k, t) = b(t) C_G(jw_k) b(t)^T.

        The uncertainty of the time-varying transfer function, shape
        ``(M, len(t_index))`` -- by default ``(M, N)`` over the whole record.
        Pass ``t_index`` to evaluate on a subset, since the full array is
        ``M x N``.

        The variance is time-dependent even though ``C_G`` is not: the
        Legendre basis weights the coefficients differently at each instant,
        and the higher orders grow towards the edges of the window. That is
        why estimates are least certain at the start and end of a record.
        """
        cov = self.cov_H_p                       # raises when unavailable
        b = self._basis if t_index is None else self._basis[t_index]
        # real by construction: b is real and C_G is Hermitian
        var = np.einsum("tp,mpq,tq->mt", b, cov, b).real
        return np.maximum(var, 0.0)

    def std_over_time(self, t_index=None) -> np.ndarray:
        """Standard deviation of H(w, t); the square root of eq. (87)."""
        return np.sqrt(self.variance_over_time(t_index))

def legendre_basis(N: int, order: int) -> np.ndarray:
    """Rescaled Legendre basis b_p(t) = L_p(2t/T - 1), sampled on N points.

    Returns a real array of shape ``(N, order+1)``.

    The sample mean is removed from every p >= 1. On a finite sampled window the
    continuous property (1/T) int b_p dt = 0 does not hold exactly, so without this
    every time-varying regressor leaks into the DC bin.
    """
    x = 2.0 * np.arange(N) / N - 1.0
    b = legvander(x, order)                       # (N, order+1)
    b[:, 1:] -= b[:, 1:].mean(axis=0, keepdims=True)
    return b

def legendre_spectra(b: np.ndarray) -> np.ndarray:
    """Scaled DFT of the basis functions: B_p(k) = FFT(b_p)/N.

    Kept at full length N. The skirts are two-sided about their own centre, so a
    column centred at harmonic k' is indexed as ``B[(K_w - k') % N, p]``.

    return np.fft.fft(b, axis=0) / b.shape[0]

TIM 2021 eq. (58), or TIM 2022 eq. (21) when detrending is in use.

Without detrending: target skirt, other harmonics in band, trend block at DC, transient polynomial. The trend block is present in every band, as the paper prescribes; bands where it carries nothing are handled by the pruning of Algorithm 2 step 6 on statistical grounds, not by excluding it up front.

With detrending, two things change (2022 eq. 21). The skirts are multiplied by the filter response F(k), because the data they model has been through that filter. And the trend block disappears -- the trend was removed rather than modelled, which is the entire point -- replaced by the filter's own boundary regressors.

    by the filter response ``F(k)``, because the data they model has been
    through that filter. And the trend block disappears -- the trend was
    removed rather than modelled, which is the entire point -- replaced by the
    filter's own boundary regressors.
    """
    N = B.shape[0]
    blocks, cmap, j = [], {}, 0

    def add(name, block):
        nonlocal j
        cmap[name] = slice(j, j + block.shape[1])
        blocks.append(block)
        j += block.shape[1]

    F = detrend.frequency_response(K_w, N)[:, None] if detrend is not None else 1.0

    add("target", F * B[(K_w - k_e) % N, : Np + 1])
    for kp in centres:
        add(f"h{kp}", F * B[(K_w - kp) % N, : Np + 1])

    if detrend is None:
        # q = 0 is identically zero off DC; its coefficient is the mean, V[0].
        if Nq >= 1:
            add("drift", B[K_w, 1 : Nq + 1])
    elif detrend.n_extra_params:
        add("boundary", detrend.extra_regressors(K_w, N))

    xi = 2.0 * (K_w - K_w[0]) / (K_w[-1] - K_w[0]) - 1.0
    add("transient", legvander(xi, Na).astype(complex))
    return np.hstack(blocks), cmap

    Parameters
    ----------
    response, excitation, fs, P, H_exc
        As for :func:`bltva`.
    Np, Nq, Na : int
        Upper bounds on the model orders, used to size the sliding band.
    dof : int
        Degrees of freedom left after the fit in each band, eq. (39).
        Larger means a wider band, so a smoother but less local estimate.
    safety : float

    step : int or None

        Na = floor(3P/4) - Np - d + 1

def check_identifiability(P, Np, Nq, Na):
    """Hallemans TIM 2021 eq. (49): Nq + 3*Np + Na + 1 < 2P - 1.

    A band holds at most three harmonics of K_nl, so the largest number of
    parameters any band has to support is ``n_theta_max = Nq + 3*Np + Na + 1``.
    The band itself spans at most 2P+1 bins, of which up to three are removed,
    so there must be fewer parameters than that for the fit to be determined.

    Returns ``n_theta_max``. Raises when the condition fails -- as the paper
    puts it, at that point one should redo the measurement with more periods.
    """
    n_theta_max = Nq + 3 * Np + Na + 1
    if n_theta_max >= 2 * P - 1:
        raise ValueError(
            f"eq. (49) violated: Nq + 3*Np + Na + 1 = {n_theta_max} is not "
            f"below 2P - 1 = {2 * P - 1} for P={P}, Np={Np}, Nq={Nq}, Na={Na}. "
            "There are more parameters than a band can support. Measure more "
            "periods, or lower the model orders.")
    return n_theta_max

    _warn_if_bands_are_huge(k_exc, N, band_halfwidth, P)

                                        Np=Np, Nq=Nq, Na=Na, detrend=detrend)

                        fit, B, N, Np, odd_free, fit["sigma2_bins"])

            "k_e": fit["k_e"],
            "f_exc": fit["k_e"] / T,
            "N_w": int(K_w.size),

            "n_unsupported_dropped": fit["n_unsupported_dropped"],

        var_distortion_even=var_even, var_distortion_odd=var_odd,
        response_power=Y_exc, diagnostics=diagnostics, _basis=b[:, : Np + 1],
    )

def max_elaboration_points(indexes_multisine_freq, n_samples):
    """Largest ``Npts_elab`` whose band fits inside the spectrum at every frequency.

Impedance and the variance of its error, per frequency and instant.

DMFA is a linear estimator of the envelope -- band selection, a diagonal weighting by the filter, and an inverse transform are all linear -- so the variance of its output is the covariance of a linear map applied to the measurement noise. That is the same route BLTVA takes, and it gives the expression of Chukwu et al. (2022) eq. (19)-(20):

    # over, not the width of the extracted band.

          frequencies,
          sampling_time,
          tol=ON_BIN_TOLERANCE,

    ``freq_axis`` must be ``fftshift(fftfreq(n, sampling_time))`` built with
    the **same n as the spectrum you are going to index**, because the bin
    spacing ``1/(n*sampling_time)`` is taken from its length. Mixing a
    full-record axis with a windowed spectrum, or the reverse, silently reads
    the wrong bins; that is the single easiest way to misuse this function.

    Uses round rather than ceil: the aim is the *nearest* bin. With ceil a
    frequency landing a hair above a bin centre is pushed to the next one.

    A multisine is designed so that every tone falls exactly on a bin -- that
    is what makes the DFT leakage-free. A tone further than ``tol`` bins from
    a centre therefore means the record length and the multisine period
    disagree, so it raises rather than rounding quietly. Pass ``tol=None`` to
    index an arbitrary frequency list, accepting the leakage that implies.
    """
    freq_axis = np.asarray(freq_axis)
    frequencies = np.asarray(frequencies, dtype=float)
    index_f0 = _zero_frequency_index(freq_axis)
    n = freq_axis.size

        if residual.max() > tol:

            df = 1.0 / (n * sampling_time)

                f"{frequencies[worst]:g} Hz lies {residual[worst]:.3g} bins "
                f"from a bin centre (bin spacing {df:g} Hz). A multisine tone "
                "should land exactly on a bin; check that the record is a "
                "whole number of multisine periods and that freq_axis was "
                "built with the same n as the spectrum. Pass tol=None to "
                "index off-grid frequencies anyway.")

        raise ValueError(
            f"frequencies must lie below the Nyquist frequency {nyquist:g} Hz; "
            f"the highest requested is {np.abs(frequencies).max():g} Hz")

def search_freq_indexes(
          spectrum,
          freq_axis,
          frequencies,
          sampling_time
          ):
        """Refine the computed bin indexes by finding the local spectral peak.

        ``spectrum`` must be a *shifted spectrum*, not a time series: the
        search indexes it with DFT bin numbers. Use this when the tones may
        not land exactly where asked -- a generator whose clock differs
        slightly from the acquisition card's, say. For a synthesised record
        :func:`compute_freq_indexes` is exact and this adds nothing.

        The window is bounded two ways: by half the distance to the nearer
        neighbouring excited frequency, and by the gap to the nearest
        neighbouring excited *bin*. Without the second bound the search can
        lock onto a neighbour, and when the two are equally strong ``argmax``
        silently prefers the lower index. Adjacent excited bins leave no room
        to search at all, and the computed index stands.
        """
        frequencies = np.asarray(frequencies, dtype=float)
        spectrum = np.asarray(spectrum)
        if spectrum.size != np.asarray(freq_axis).size:
            raise ValueError(
                f"spectrum has {spectrum.size} bins but freq_axis has "
                f"{np.asarray(freq_axis).size}. They must describe the same "
                "transform -- mixing a windowed spectrum with a full-record "
                "axis, or the reverse, reads the wrong bins.")
        # tol=None: the whole point here is that the tones may be off-grid.
        guesses = np.asarray(
            compute_freq_indexes(freq_axis, frequencies, sampling_time,
                                 tol=None)[0], dtype=int)
        index_f0 = _zero_frequency_index(freq_axis)

        # Distance in Hz to the nearer neighbouring excited frequency. The
        # outermost tones have a neighbour on one side only; DC bounds the
        # first from below, and the last simply reuses its lower gap rather
        # than inventing a width for the side that has nothing on it.
        dist = np.empty(frequencies.size)
        if frequencies.size == 1:
            dist[0] = frequencies[0]
        else:
            dist[0] = min(frequencies[1] - frequencies[0], frequencies[0])
            dist[-1] = frequencies[-1] - frequencies[-2]
            for f in range(1, frequencies.size - 1):
                dist[f] = min(frequencies[f] - frequencies[f - 1],
                              frequencies[f + 1] - frequencies[f])
        half_hz = np.floor(dist * sampling_time * np.asarray(freq_axis).size / 4).astype(int)

        # The window must never reach a neighbouring excited bin, or the search
        # can lock onto the neighbour -- and when the two are equally strong,
        # argmax silently prefers the lower index. Adjacent excited bins
        # therefore leave no room to search and the computed index stands.
        if guesses.size == 1:
            half_bins = half_hz
        else:
            gaps = np.diff(guesses)
            nearest = np.empty(guesses.size, dtype=int)
            nearest[0], nearest[-1] = gaps[0], gaps[-1]
            nearest[1:-1] = np.minimum(gaps[:-1], gaps[1:])
            half_bins = np.minimum(half_hz, (nearest - 1) // 2)
        half_bins = np.maximum(half_bins, 0)

        index_multisine_freq = np.zeros(frequencies.size, dtype='int64')
        for f in range(frequencies.size):
            lo = max(0, guesses[f] - half_bins[f])
            hi = min(spectrum.size, guesses[f] + half_bins[f] + 1)
            index_multisine_freq[f] = lo + int(np.argmax(np.abs(spectrum[lo:hi])))
        return index_multisine_freq.tolist(), index_f0

Lock-in amplifier¶

lock_in_amp ¶

Digital lock-in amplifier for multi-frequency impedance.

The classical instrument, implemented offline. For each excited frequency the record is multiplied ("mixed") with a cosine and a sine at that frequency and the product low-pass filtered, which leaves the slowly varying complex amplitude of that tone. The ratio of the voltage and current amplitudes is Z(f, t).

Mathematics

Write the response near the k-th tone as a carrier with a slowly varying phasor::

v(t) = A_v(t) * cos(w_k * t + phi_v(t)),      w_k = 2*pi*f_k

Mixing with the in-phase and quadrature references gives

v(t) * cos(w_k t) = (A_v/2) * cos(phi_v) + (A_v/2) * cos(2 w_k t + phi_v)
v(t) * sin(w_k t) = -(A_v/2) * sin(phi_v) + (A_v/2) * sin(2 w_k t + phi_v)

so a low-pass filter that rejects 2*w_k and every other excited tone leaves X = (A_v/2) cos(phi_v) and Y = -(A_v/2) sin(phi_v). Twice the complex combination is the phasor::

V(t) = 2 * (X - 1j*Y) = A_v(t) * exp(1j * phi_v(t))

The same is done for the current, and

Z(f_k, t) = V(t) / I(t)
Choosing the integrator

The low-pass filter is the whole method, because it must reject

  • the image at 2*f_k produced by the mixing, and
  • every other tone of the multisine, which after mixing appears at the difference frequency |f_j - f_k|.

The second requirement is the binding one. For a multisine whose tones are all harmonics of a base frequency f_b, a boxcar average over exactly an integer number of periods of f_b has spectral nulls at every multiple of f_b -- that is, at every difference frequency that can occur. It rejects all of them exactly.

A Hann (or any tapered) window has its nulls in the same places but a mainlobe twice as wide, so with a one-period window the nearest harmonic sits inside the mainlobe and is not rejected. A Hann integrator therefore needs at least two base periods. :func:integrator_length enforces this, and :func:tone_rejection measures it.

The integrator length is also the time resolution: a window of m periods of f_b cannot follow anything faster than m / f_b seconds, which is the same trade STFT makes with its window and DMFA with its bandwidth.

Edges

The output within half an integrator length of either end of the record is computed from a window that extends past the data. This module reflects the signal at the boundaries, which is exact for an envelope with zero slope there and good otherwise, and :func:valid_mask marks the affected samples so they can be excluded from a fit.

    ----------

        demodulated.
    n_periods : int

            "rate or the base frequency.")

def tone_rejection(kernel, sampling_time, frequencies, f_k):
    """How much the integrator suppresses each other tone, in dB.

    After mixing at ``f_k`` a tone at ``f_j`` lands at ``|f_j - f_k|``; this
    evaluates the kernel's frequency response there. Large positive numbers
    are good. A boxcar over whole base periods gives essentially infinite
    rejection (nulls), limited only by arithmetic.

    The returned array has one entry per frequency, **including ``f_k``
    itself**, whose offset is zero and whose "rejection" is therefore 0 dB by
    construction. Drop that entry before taking a worst case over the others,
    or the answer is always 0 dB.

    offsets = np.abs(np.asarray(frequencies) - f_k)

    """Lock-in impedance at one frequency, by mixing and low-pass filtering.

    Parameters
    ----------
    t, v, i : ndarray
        Time, voltage and current, all the same length.
    dt : float
        Sampling time in seconds.
    f0 : float
        The frequency to demodulate, in Hz.
    samples_window : int
        Length of the integrator. Use :func:`integrator_length` to get a value
        that rejects the other tones.
    window : {'boxcar', 'hann'}

    Returns
    -------
    ndarray
        Complex ``Z(f0, t)``, one value per input sample. Samples within half
        an integrator length of either end rest on reflected data; see
        :func:`valid_mask`.
    """
    omega = 2 * np.pi * f0
    kernel = integrator_kernel(samples_window, window)

    ref_cos, ref_sin = np.cos(omega * t), np.sin(omega * t)

    # result is the phasor itself rather than half of it. It cancels in the
    # ratio below, but makes V and I meaningful on their own.
    V = 2 * (_lowpass(v * ref_cos, kernel) - 1j * _lowpass(v * ref_sin, kernel))

def local_ls(t, x, omega, idx, Nw):
    """Fit cos, sin, an offset and a local slope in a window centred on ``idx``.

    Returns the complex amplitude **referenced to the centre of the window**,
    not to t = 0. The reference cancels in ``V/I`` because both are fitted on
    the same window, which is why :func:`lia_impedance_ls` is correct; a
    caller using this function alone must undo the ``exp(-1j*omega*t0)``
    itself.
    """
    half = Nw // 2
    sl = slice(max(0, idx - half), min(len(t), idx + half + 1))
    tt, xx = t[sl], x[sl]
    tau = tt - tt.mean()

    design = np.column_stack([np.cos(omega * tau), np.sin(omega * tau),
                              np.ones_like(tau), tau])
    weight = np.sqrt(np.hanning(tau.size + 2)[1:-1])
    theta, *_ = np.linalg.lstsq(design * weight[:, None], xx * weight,
                                rcond=None)
    return theta[0] - 1j * theta[1]

    Fits a cosine, a sine, an offset and a linear slope in a sliding window.

    instants, which is already finer than the integrator can resolve.

    -------

Goertzel filter¶

goertzel ¶

Goertzel filter for multi-frequency impedance.

The Goertzel algorithm evaluates a single DFT bin with a second-order recurrence instead of a transform, costing O(N) per bin rather than O(N log N) for all of them. It is the standard way to detect a handful of known tones -- DTMF decoding is the textbook case -- and it is attractive here because a multisine measurement wants exactly a handful of known tones.

Mathematics

For a block of N samples and a bin k (the frequency in units of the block's own resolution, k = f * N * dt), define

w     = 2*pi*k/N
coeff = 2*cos(w)

and run, from s1 = s2 = 0,

s[n]  = x[n] + coeff*s[n-1] - s[n-2],     n = 0 .. N-1

After the last sample the DFT value is recovered from the final two states::

X[k] = (exp(1j*w) * s[N-1] - s[N-2]) * exp(-1j*2*pi*k)

That combination is asymmetric, and the symmetric-looking rearrangement is wrong::

X[k] = (s[N-1] - exp(-1j*w) * s[N-2]) * exp(-1j*2*pi*k)    # WRONG

It has the right magnitude and is out by exactly exp(-1j*w) in phase. The error cancels in any ratio -- including V/I -- so an impedance test will not catch it; only a comparison against the DFT itself will, which is what test_output_formula_is_not_the_tempting_rearrangement does. The correct form is what one further iteration with a zero input would give, s[N] - exp(-1j*w)*s[N-1], written closed-form.

The trailing factor is unity whenever k is an integer, which is the usual presentation. Keeping it is the generalised Goertzel of Sysel and Rajmic, and it makes the result correct for a non-integer k as well -- useful when a tone does not fall exactly on a bin of the block you chose.

References

Goertzel, Am. Math. Monthly 65 (1958) 34 -- the original recurrence.

Sysel and Rajmic, EURASIP J. Adv. Signal Process. (2012) 56 -- the generalisation to non-integer bins, which is the form implemented here.

Only two state variables are carried, so nothing but the recurrence has to be stored. That is what makes the filter usable on a stream, one sample at a time, with no buffer: see :class:GoertzelFilter.

What it is, and is not, good for

Offline, on the records this package deals with, Goertzel is slower than an FFT. The crossover is at roughly n_bins ~ log2(N): below that Goertzel wins, above it the FFT does. A 13-tone multisine over a 20 000-sample block has log2(N) = 14.3, so the two are a wash, and the FFT is better optimised.

It is included because:

  • it is a standard estimator and the package exists to collect them;
  • it computes exactly the same quantity as a rectangular-window STFT, which makes it a useful independent check on that path;
  • its per-sample recurrence is the natural route to online processing, where no FFT is possible because the record has not finished.

class GoertzelFilter:
    """One bin of a running DFT, updated a sample at a time.

    The offline functions above exist because this package analyses recorded
    files, but the recurrence itself needs no record: it carries two numbers.
    This class is the streaming form, for an acquisition that has not
    finished.

    >>> filt = GoertzelFilter(frequency=0.05, sampling_time=1e-3, block=20000)
    >>> for sample in stream:                           # doctest: +SKIP
    ...     value = filt.push(sample)
    ...     if value is not None:
    ...         ...                                     # one block completed

    ``push`` returns ``None`` until a block is complete, then the complex DFT
    value for that block, and resets itself for the next one.
    """

    def __init__(self, frequency, sampling_time, block):
        self.block = int(block)
        self.k = float(frequency) * self.block * float(sampling_time)
        self.omega = 2 * np.pi * self.k / self.block
        self.coeff = 2 * np.cos(self.omega)
        self.reset()

    def reset(self):
        self._s1 = 0.0
        self._s2 = 0.0
        self._n = 0

    def push(self, sample):
        """Feed one sample; returns the block's DFT value when it completes."""
        s = float(sample) + self.coeff * self._s1 - self._s2
        self._s2, self._s1 = self._s1, s
        self._n += 1
        if self._n < self.block:
            return None
        value = (np.exp(1j * self.omega) * self._s1 - self._s2) * \
            np.exp(-1j * 2 * np.pi * self.k)
        self.reset()
        return value

def goertzel_dft(block, bins):
    """DFT values at the given bins, by recurrence rather than transform.

    Parameters
    ----------
    block : ndarray
        Either one block, shape ``(N,)``, or several, shape ``(n_blocks, N)``.
    bins : array_like
        Bin indices ``k = f * N * dt``. May be non-integer; the generalised
        correction is always applied.

    Returns
    -------
    ndarray
        Complex, shape ``(n_bins,)`` or ``(n_blocks, n_bins)``. Scaled like
        :func:`numpy.fft.fft` -- that is, **not** divided by ``N``.
    """
    block = np.asarray(block, dtype=float)
    single = block.ndim == 1
    if single:
        block = block[None, :]
    if block.ndim != 2:
        raise ValueError("block must be 1-D or 2-D")

    n_blocks, n = block.shape
    k = np.asarray(bins, dtype=float)
    omega = 2 * np.pi * k / n
    coeff = 2 * np.cos(omega)

    s1 = np.zeros((n_blocks, k.size))
    s2 = np.zeros((n_blocks, k.size))
    for sample in range(n):
        s = block[:, sample][:, None] + coeff[None, :] * s1 - s2
        s2, s1 = s1, s

    values = (np.exp(1j * omega)[None, :] * s1 - s2) * \
        np.exp(-1j * 2 * np.pi * k)[None, :]
    return values[0] if single else values

def goertzel_eis(voltage, current, frequencies, period, sampling_time):
    """Impedance per block, computed with the Goertzel recurrence.

    The signature mirrors
    :func:`deistools.processing.stft_functions.estimate_impedance`, and so
    does the result: the record is cut into consecutive blocks of ``period``
    seconds and one spectrum is produced per block, stamped at its midpoint.
    Only the excited bins are evaluated, which is the whole point of the
    algorithm.

    ``period`` must hold a whole number of periods of every tone, for the same
    reason a rectangular STFT window must: otherwise each bin picks up the
    others.

    Returns
    -------
    (impedance, time) : ndarray, ndarray
        ``impedance`` has shape ``(n_frequencies, n_blocks)``.
    """
    voltage = np.asarray(voltage, dtype=float)
    current = np.asarray(current, dtype=float)
    if voltage.shape != current.shape or voltage.ndim != 1:
        raise ValueError("voltage and current must be 1-D arrays of equal length")

    samples_window = int(round(period / sampling_time))
    if samples_window < 2:
        raise ValueError("period is shorter than two samples")
    n_blocks = voltage.size // samples_window
    if n_blocks < 1:
        raise ValueError(
            f"the record holds {voltage.size} samples, less than one block of "
            f"{samples_window}")

    usable = n_blocks * samples_window
    v = voltage[:usable].reshape(n_blocks, samples_window)
    i = current[:usable].reshape(n_blocks, samples_window)

    bins = np.asarray(frequencies, dtype=float) * period
    V = goertzel_dft(v, bins)
    I = goertzel_dft(i, bins)

    time = (np.arange(n_blocks) + 0.5) * period
    return (V / I).T, time

def create_fermi_dirac_fun(fr, fc, bw, n):
    """
    Create a digital filter shaped as a symmetric Fermi-Dirac function.

        Y = cosh(n) / (cosh(n*X) + cosh(n)),    X = (fr - fc) / bw

    Evaluated as ``1 / (1 + cosh(n*X)/cosh(n))`` with the ratio of hyperbolic
    cosines expanded in exponentials. Written literally, ``cosh(n*X)``
    overflows for the far tails of a wide axis -- the answer is still right,
    since an infinite denominator correctly gives zero, but it warns on every
    call. The identity

        cosh(a)/cosh(b) = exp(|a| - b) * (1 + exp(-2|a|)) / (1 + exp(-2b))

    is therefore taken in log space and finished with a numerically stable
    logistic, so no exponential of a large positive number is ever formed.
    """
    a = np.abs(n * np.asarray(fr - fc, dtype=float) / bw)
    b = abs(n)
    # log of cosh(n*X)/cosh(n); both exponentials have non-positive arguments
    log_ratio = (a - b) + np.log1p(np.exp(-2.0 * a)) - np.log1p(np.exp(-2.0 * b))
    # 1/(1 + exp(log_ratio)), evaluated without overflow for either sign
    small = np.exp(-np.abs(log_ratio))
    return np.where(log_ratio >= 0.0, small / (1.0 + small), 1.0 / (1.0 + small))

    ``alpha`` is the roll-off, from a rectangle at 0 to a Hann-shaped bell at
    1. It plays the same role as ``n`` in the Fermi-Dirac filter but inverted:
    small ``alpha`` is flat and rings, large ``alpha`` is smooth and does not.

    Offered beside the Fermi-Dirac because it is the shape most readers will
    recognise, and because it is **compactly supported** -- exactly zero beyond
    ``bw*(1 + alpha)`` -- so extracting a finite block of bins around a tone
    truncates nothing. The Fermi-Dirac has exponential tails and needs a block
    wide enough for them to have decayed.

    On the transistor system the Fermi-Dirac at ``n = 2`` still measures best
    (worst-case 5.0e-04 against 7.4e-04 for ``alpha = 1``), because on a
    band-limited extraction the dominant error is time-domain ringing and its
    time concentration is exceptional. See the method documentation.
    """
    if not 0 < alpha <= 1:
        raise ValueError("alpha must be in (0, 1]")
    x = np.abs(np.asarray(fr, dtype=float) - fc) / bw
    out = np.zeros_like(x)
    out[x <= 1 - alpha] = 1.0
    edge = (x > 1 - alpha) & (x < 1 + alpha)
    out[edge] = 0.5 * (1 + np.cos(np.pi * (x[edge] - 1 + alpha) / (2 * alpha)))
    return out

Best linear approximation per burst¶

bla ¶

Best linear approximation per burst, after Pintelon, Louarroudi and Lataire.

The short-time Fourier estimator in :mod:~deistools.processing.stft_functions reads the excited bins of each window and divides. That is enough to get an impedance and nothing else: a single window gives no way to say whether the number it produced is limited by measurement noise, by nonlinearity, or by the cell changing while the window was open.

This module adds that. It keeps STFT's assumption -- the system is whatever it is inside one window, with no model of how it varies -- and uses the bins STFT throws away to classify the error.

The one structural fact

Cut a record into windows of P whole multisine periods. The DFT of a window has fundamental 1/(P*Tp), so a tone at harmonic h of the multisine lands on bin P*h and only every P-th bin is a harmonic of the multisine at all. A nonlinear system of the PISPO class (period in, same period out) answers a periodic input with a periodic output, so its distortion is harmonically related to the input and can land only on those bins. That splits the spectrum of one burst into four classes:

========================  ====================================
bins                      what is there
========================  ====================================
``k = P*h``, h excited    signal (+ everything below)
``k = P*m``, m odd        odd-order distortion + noise + drift
``k = P*m``, m even       even-order distortion + noise + drift
``k`` not a multiple of P noise + drift
========================  ====================================

This requires P >= 2. At P = 1 the window fundamental is the multisine fundamental, every bin is a harmonic, and the fourth class is empty. On the package's 13-tone grid, in band, :func:classify_bins counts

===  =======  =====  ======  ========
P    noise    odd    even    excited
===  =======  =====  ======  ========
1    0        168    180     13
2    301      138    150     13
4    903      138    150     13
8    2107     138    150     13
===  =======  =====  ======  ========

so the noise class appears only at P >= 2 and then grows with the burst, while the detection lines stay put. Since one period is exactly the window the plain STFT prefers, the uncertainty is bought with time resolution and there is no way around that.

What the noise class actually contains

On a time-varying cell the non-harmonic bins are not noise alone. The time variation convolves each excited line into its neighbours (Lataire 2012 eq. 48: a linear-in-time variation has B_1(k) ~ 1/k), so every tone grows a skirt, and with a dozen tones the skirts cover the band. Measured on the transistor system, a 40 s burst cut from the usual 400 s record, as a ratio to the pure-noise floor at the same bins:

================  =======
distance to the   ratio to
nearest tone      noise floor
================  =======
1-2 bins          7656
6-10 bins         463
21-50 bins        71
51-100 bins       44
================  =======

It decays, and it never arrives. So a noise level read off these bins is an upper bound, and on a strongly varying cell a loose one. That is not a defect of the implementation; separating the two needs a model of the variation, which is what :mod:~deistools.processing.bltva is for and what this module deliberately does not assume.

:func:ratio_noise_to_time_variation says which case you are in, so the bound can be read correctly rather than trusted blindly.

class BurstBLA:
    """What one burst says about itself.

    The three ``std_*`` attributes are **measured levels, not a
    decomposition**: each is what the bins of one class imply for the
    standard deviation of ``impedance``, with nothing subtracted. They are
    reported that way on purpose. Subtracting one from another is how the
    distortion is normally quoted, and it is available from
    :meth:`distortion_odd` and :meth:`distortion_even`, but the subtraction
    has two failure modes that a stored, already-subtracted number would
    hide -- see those methods.

    Attributes
    ----------
    impedance : (M,) complex
        ``V/I`` at the excited bins -- the same number the STFT returns.
    std_noise : (M,) float
        Level at the non-harmonic bins. Noise alone on a time-invariant cell;
        noise *plus the time-variation skirt* otherwise, so an **upper
        bound**. :attr:`r_ntv` says which.
    std_odd_lines, std_even_lines : (M,) float or None
        Level at the unexcited odd and even harmonics. Each contains the
        noise as well as any distortion of that parity. ``None`` when the
        grid leaves no harmonic of that parity free in band.
    r_ntv : float
        Which error dominates the non-harmonic bins. Near 1 means the time
        variation does; well above 1 means noise does. See
        :func:`ratio_noise_to_time_variation`.
    n_bins : dict
        How many bins fell in each class, so a thin estimate is visible.
    """

    __slots__ = ("impedance", "std_noise", "std_odd_lines",
                 "std_even_lines", "r_ntv", "n_bins", "n_local")

    def __init__(self, impedance, std_noise, std_odd_lines,
                 std_even_lines, r_ntv, n_bins, n_local=30):
        self.impedance = impedance
        self.std_noise = std_noise
        self.std_odd_lines = std_odd_lines
        self.std_even_lines = std_even_lines
        self.r_ntv = r_ntv
        self.n_bins = n_bins
        self.n_local = n_local

    def __repr__(self):
        return (f"BurstBLA({self.impedance.size} tones, "
                f"r_ntv={self.r_ntv:.2f}, bins={self.n_bins})")

    def dominant_error(self, tolerance=3.0):
        """``'time variation'`` or ``'noise'``, from :attr:`r_ntv`.

        ``tolerance`` is how far above 1 the ratio must sit before the
        residual is called noise. The statistic is itself noisy on a short
        burst, so a wide margin is the honest default.

        The test needs a residual to work on. On a noiseless simulation the
        non-harmonic bins hold nothing but round-off and the answer is
        meaningless -- measured at 0.86 for a stationary noiseless cell,
        which would read as "time variation" for a system that has none.
        Real records always have noise; simulated ones should be given some.
        """
        return "noise" if self.r_ntv > tolerance else "time variation"

    def _excess(self, level, z=3.0):
        """``sqrt(level^2 - noise^2)``, NaN unless the excess is significant.

        A positive difference is not by itself evidence. Each level is a mean
        of ``n_local`` bin powers, so it carries a relative standard error of
        ``1/sqrt(n_local)``, and their difference about ``sqrt(2/n_local)``.
        The excess is reported only when it clears ``z`` of those, i.e.

            level^2 - noise^2  >  z * sqrt(2/n_local) * noise^2

        Without the threshold, merely requiring a positive difference fires
        on **10 of 13 tones of a linear stationary cell**, where the two
        levels agree to 2.5% and the sign is a coin toss. With it, none do.

        NaN rather than zero because the two mean different things: zero
        would claim the distortion was measured and found absent, while NaN
        says this burst cannot resolve it.
        """
        if level is None:
            return None
        noise_power = self.std_noise ** 2
        excess = level ** 2 - noise_power
        threshold = z * np.sqrt(2.0 / max(self.n_local, 1)) * noise_power
        return np.where(excess > threshold, np.sqrt(np.abs(excess)), np.nan)

    def distortion_odd(self):
        """Odd-order distortion, the noise removed. NaN where unresolvable.

        This is the one that matters for an odd multisine: odd-order
        distortion lands *on* the excited lines as well as the empty odd
        ones, so it biases the impedance, where even-order distortion only
        sits beside it.

        Two things make the result NaN, and both are information:

        * **The burst is too short to resolve it.** With ``n_local`` bins
          averaged, a power estimate carries about ``1/sqrt(n_local)``
          relative error, so when there is no real distortion the difference
          scatters about zero and half the tones come back NaN. Taking
          ``max(excess, 0)`` instead would rectify that scatter into a
          spurious positive level -- measured at 1.3e-05 on a *linear*
          stationary cell, which is exactly the false alarm this avoids.
        * **The cell is varying.** Then the non-harmonic bins carry the
          time-variation skirt and sit *above* the harmonic ones, so the
          subtraction is negative everywhere. Measured on the block-oriented
          system, which is nonlinear *and* time-varying: every tone NaN,
          although the distortion is certainly there. Check :attr:`r_ntv`
          first; if it is near 1, use
          :func:`~deistools.processing.bltva.bltva`, which models the
          variation and reports ``var_distortion_odd`` with it removed.
        """
        return self._excess(self.std_odd_lines)

    def distortion_even(self):
        """Even-order distortion, the noise removed. NaN where unresolvable.

        Same caveats as :meth:`distortion_odd`. Even-order distortion does
        not land on the excited lines of an odd multisine, so it does not
        bias the impedance; it is reported because its presence says
        something about the cell.
        """
        return self._excess(self.std_even_lines)

def classify_bins(n_samples, periods_per_window, harmonics, band_only=True):
    """Which DFT bins of one burst carry what.

    Parameters
    ----------
    n_samples : int
        Length of the burst.
    periods_per_window : int
        Whole multisine periods inside it. Must be >= 2, or the noise class
        is empty -- see the module docstring.
    harmonics : sequence of int
        Excited harmonic numbers of the multisine.
    band_only : bool
        Restrict every class to bins at or below the highest excited tone.
        Above it there is no signal to compare against and the data
        acquisition's own filtering shapes whatever is left.

    Returns
    -------
    dict of boolean masks over ``k = 1 .. n_samples//2 - 1``, with keys
    ``excited``, ``odd_nl``, ``even_nl``, ``noise`` and ``band``, plus
    ``bins`` (the bin indices themselves) and ``k_excited`` (the excited bins
    in the order ``harmonics`` gives them).
    """
    periods = int(periods_per_window)
    if periods < 2:
        raise ValueError(
            f"periods_per_window must be >= 2, got {periods}. At one period "
            "every bin of the burst is a harmonic of the multisine, so "
            "nonlinear distortion and noise land in the same places and "
            "cannot be separated. This is the price of the uncertainty "
            "estimate, paid in time resolution.")

    harmonics = np.asarray(harmonics, dtype=int)
    k = np.arange(1, n_samples // 2)
    is_harmonic = (k % periods == 0)
    order = np.where(is_harmonic, k // periods, -1)

    excited = np.isin(order, harmonics)
    free = is_harmonic & ~excited
    band = (k <= harmonics.max() * periods) if band_only else np.ones_like(k, bool)

    return {
        "bins": k,
        "k_excited": harmonics * periods,
        "excited": excited & band,
        "odd_nl": free & (order % 2 == 1) & band,
        "even_nl": free & (order % 2 == 0) & band,
        "noise": (~is_harmonic) & band,
        "band": band,
    }

ratio_noise_to_time_variation ¶

Is the residual noise, or the cell moving? Lataire 2012 eq. (33).

The two are told apart by their correlation over frequency rather than their size. Stationary noise is uncorrelated between neighbouring DFT bins. A time variation is not: it reaches each bin by convolving the excited lines with the spectrum of the variation, so neighbours share contributions. For a linear-in-time variation the ratio of the autocorrelation at lags 0 and 1 works out to exactly pi^2/6 (eq. 31), so scaling by 6/pi^2 puts "pure time variation" at 1:

R = (6/pi^2) * mean|V(k)|^2 / |mean V(k) conj(V(k+1))|

Near 1 the residual is time variation; well above 1 it is noise. Only adjacent bins of noise_mask are used, since the lag has to be a real neighbour.

Measured on one 80 s burst: 12.7 for a stationary cell with noise, 0.97 for the block-oriented system and 0.77 for the transistor -- both of which vary.

    The two are told apart by their correlation over frequency rather than
    their size. Stationary noise is uncorrelated between neighbouring DFT
    bins. A time variation is not: it reaches each bin by convolving the
    excited lines with the spectrum of the variation, so neighbours share
    contributions. For a linear-in-time variation the ratio of the
    autocorrelation at lags 0 and 1 works out to exactly ``pi^2/6``
    (eq. 31), so scaling by ``6/pi^2`` puts "pure time variation" at 1:

        R = (6/pi^2) * mean|V(k)|^2 / |mean V(k) conj(V(k+1))|

    Near 1 the residual is time variation; well above 1 it is noise. Only
    *adjacent* bins of ``noise_mask`` are used, since the lag has to be a
    real neighbour.

    Measured on one 80 s burst: 12.7 for a stationary cell with noise, 0.97
    for the block-oriented system and 0.77 for the transistor -- both of which
    vary.

    Returns ``inf`` when fewer than two adjacent pairs survive, which is the
    honest answer rather than a number built from nothing.
    """
    selected = np.flatnonzero(noise_mask)
    if selected.size < 3:
        return float("inf")
    adjacent = selected[np.flatnonzero(np.diff(bins[selected]) == 1)]
    if adjacent.size < 2:
        return float("inf")

    lag0 = np.mean(np.abs(spectrum[adjacent]) ** 2)
    lag1 = np.abs(np.mean(spectrum[adjacent] * np.conj(spectrum[adjacent + 1])))
    if lag1 == 0.0:
        return float("inf")
    return float(lag0 / lag1 / PI_SQUARED_OVER_SIX)

    """Impedance of one burst, with the error split by where it came from.

    Parameters
    ----------
    voltage, current : (n,) real
        One burst, holding exactly ``periods_per_window`` multisine periods.
    harmonics : sequence of int
        Excited harmonic numbers.
    periods_per_window : int
        Whole multisine periods in the burst, at least 2.
    n_local : int
        How many bins of a class to average for the level at each tone. More
        is steadier and less local; the default resolves the colouring of the
        noise without being noisy itself.

    Returns
    -------
    BurstBLA

    Notes
    -----
    The levels are referred to the impedance by first-order propagation,

        var(Z)/|Z|^2 = var(V)/|V|^2 + var(I)/|I|^2

    which treats the two channels as independently disturbed. That is the
    same convention :func:`~deistools.processing.dmfa_functions.extract_impedance_with_error`
    uses, so the two are comparable.
    """
    voltage = np.asarray(voltage, dtype=float)
    current = np.asarray(current, dtype=float)
    if voltage.shape != current.shape or voltage.ndim != 1:
        raise ValueError("voltage and current must be 1-D arrays of equal length")

    n = voltage.size
    classes = classify_bins(n, periods_per_window, harmonics)
    k = classes["bins"]
    k_exc = classes["k_excited"]
    if k_exc.max() >= k[-1]:
        raise ValueError(
            f"the highest excited harmonic sits at bin {k_exc.max()}, at or "
            f"above the burst's Nyquist bin {k[-1] + 1}")

    V = np.fft.fft(voltage)[1:n // 2] / n
    I = np.fft.fft(current)[1:n // 2] / n
    index = k_exc - 1                                 # k starts at 1

    impedance = V[index] / I[index]
    power_v, power_i = np.abs(V) ** 2, np.abs(I) ** 2
    relative = np.abs(impedance) ** 2

    def level(mask):
        """Level at one class of bins, referred to the impedance."""
        if not mask.any():
            return None
        lv, _ = _local_power(power_v, mask, k, k_exc, n_local)
        li, _ = _local_power(power_i, mask, k, k_exc, n_local)
        return np.sqrt(relative * (lv / power_v[index] + li / power_i[index]))

    return BurstBLA(
        impedance=impedance,
        std_noise=level(classes["noise"]),
        std_odd_lines=level(classes["odd_nl"]),
        std_even_lines=level(classes["even_nl"]),
        r_ntv=ratio_noise_to_time_variation(V, classes["noise"], k),
        n_bins={name: int(classes[name].sum())
                for name in ("excited", "odd_nl", "even_nl", "noise")},
        n_local=n_local,
    )

def bla_eis(voltage, current, period, sampling_time, harmonics,
            periods_per_window=4, n_local=30):
    """Sliding bursts over a whole record: STFT, with the error attributed.

    Parameters
    ----------
    voltage, current : (N,) real
        The record.
    period : float
        One multisine period, in **seconds**.
    sampling_time : float
        1/fs.
    harmonics : sequence of int
        Excited harmonic numbers, so that tone ``m`` is at
        ``harmonics[m] / period`` Hz.
    periods_per_window : int
        Multisine periods per burst, at least 2. This is the time resolution
        and it cannot be 1 -- see :func:`classify_bins`.
    n_local : int
        Bins averaged for each level; passed to :func:`burst_bla`.

    Returns
    -------
    (results, t) : list of BurstBLA, (n_bursts,) float
        One entry per burst, stamped at the burst midpoint.
    """

    current = np.asarray(current, dtype=float)
    samples = int(round(period / sampling_time)) * int(periods_per_window)
    if samples < 4:
        raise ValueError("burst shorter than four samples")

    n_bursts = voltage.size // samples

                                 periods_per_window, n_local))

Detrending¶

detrending ¶

Trend removal for BLTVA, following Hallemans et al., IEEE TIM 71 (2022) 6501711.

Why this is not a preprocessing step

A trend cannot simply be subtracted before estimation. Whatever filter removes it also shapes the signal of interest and the noise, and the estimator has to know about that shaping or it will report a biased transfer function with wrong uncertainties. Removing a trend therefore changes four things at once (2022 paper, eq. 18-27):

  1. every skirt regressor is multiplied by the filter response F(k) (eq. 21)
  2. the cost function is weighted by W = (F F^H)^-1 (eq. 26)
  3. the filter's boundary effects add their own regressors (eq. 21)
  4. the transient order Na shrinks by the order of the filter (eq. 22)

A strategy here is consequently not "a function that returns a cleaned signal". It is the bundle of those four things, which is what the protocol below encodes. A strategy that cannot report its frequency_response cannot be used safely, because step 2 would be impossible.

The weighting is what makes differencing free: it attenuates low frequencies and amplifies high ones, but it does the same to the signal and the noise, so the signal-to-noise ratio at every bin is unchanged (eq. 20). A naive low-pass-and-subtract has no such guarantee -- it would destroy exactly the low-frequency impedance information the measurement is for -- which is why frequency_response is mandatory rather than optional.

Why only differencing works here

Of the strategies in this module, only differencing may be passed to BLTVA. That is not an implementation gap; it follows from what the weighting does, and the reason is worth stating because it is easy to assume the opposite. (Differencing is also not usually the best option -- plain Nq, with no detrending at all, beats it unless eq. (49) caps Nq too low. See :class:Differencing.)

A filter applied by circular convolution is diagonal in frequency: it multiplies bin k by F(k) and nothing else. Trend and signal that share a bin are scaled by the same number, so

|T(k)| / |S(k)|   is unchanged, for every k and every diagonal filter

-- measured here as bit-identical before and after. The filter cannot separate them, because at a single bin there is nothing to separate them with. Step 2 then undoes even the attenuation: for a real, zero-phase response F/|F| = 1, so the weighted system is identical to the one built from the raw record (verified to 5.6e-17 on the skirt regressors). What survives is only the damage: the trend block of eq. (58) has been deleted, the trend is still in the data, and nothing models it. Measured on the 2022 paper's own trend, with F(k) = 1 exactly -- a filter that does nothing at all, which the protocol happily accepts:

==========================================  ==========
configuration                               error at the lowest tone
==========================================  ==========
no trend, Nq = 5                              2.2e-04
trend, Nq = 5, no detrending                  1.6e-02
trend, ``F(k) = 1`` "detrending"              2.6e+00
==========================================  ==========

A moving average does score well in that test (1.8e-04), which looks like a refutation until one varies the averaging length: L = 101, 401 and 1601 all return 1.8e-04. An answer that does not depend on the averaging length is not coming from the averaging. It comes from the 1/|F(k)| weighting applied to the transient block, which eq. (21) does not multiply by F: since F ~ k^2 near DC for any boxcar, the weighting hands the transient polynomial a k^-2 envelope, and that reshaped basis absorbs the trend skirt. The trend removal is an accident of the reparametrisation, and a Butterworth low-pass -- same protocol, different 1/|F| shape -- scores 2.6e-02, worse than no detrending at all.

Differencing escapes all of this because it is not diagonal. The zero-prepend of eq. (12) makes Delta^d annihilate a degree-d-1 polynomial identically in the time domain, which no multiplication in frequency can do, and leaves a boundary term that step 3 models exactly. Its F(k) = (1 - z_k^-1)^d is also complex, so F/|F| is a phase ramp that the magnitude weighting does not cancel.

The non-circular route is closed for the others by eq. (49) rather than by principle: a causal length-L moving average with a zero-padded history would annihilate a constant exactly, but its boundary term needs L-1 regressors -- 400 columns for L = 401, against the 2P-1 = 39 a band can support.

So the other three strategies are provided for the estimators that have no weighting to undo, and for studying what naive detrending costs. They refuse to be used as a BLTVA weighting factor, and :func:check_response is the test that decides which category a new strategy falls into.

Which strategy for which estimator

Detrending is an argument to the BLTVA call rather than state on :class:~deistools.processing.mfa.MultiFrequencyAnalysis, because only BLTVA can compensate for the shaping. The other estimators have no weighting at all, so for them whatever a filter removes is simply gone, and the choice inverts:

=======================  =====================  =====================
strategy                 BLTVA                  DMFA / STFT
=======================  =====================  =====================
:class:`Differencing`    the only one that      **destroys the
                         works                  signal**
:class:`MovingAverage`   refused                at best 1.7x, and not
                                                consistently
:class:`LowPassRemoval`  refused                no help on an
                                                overlapping trend
:class:`PolynomialFit`   refused; use ``Nq``    the only one that
                                                reliably helps
=======================  =====================  =====================

The two columns are exact complements, and one fact explains both. A diagonal filter cannot separate trend from signal inside a shared bin, so neither diagonal strategy helps anywhere. What remains is whether the estimator can undo an attenuation: BLTVA can, which is what lets differencing trade the whole low-frequency band away and get it back, so only differencing works there. DMFA and STFT cannot, so only the non-diagonal strategy -- the polynomial fit -- is any use, and it pays in distortion instead.

Never pass differencing to DMFA or STFT. Differencing(1) attenuates the lowest excited bin of a 160000-sample record to |F| = 3e-04; the measured DMFA error at that tone is 1.00e+00, i.e. the tone is gone. In BLTVA the same attenuation costs nothing, because step 2 divides it back out. This is the single most dangerous thing in this module, and the reason frequency_response is mandatory: it is the only way to see the 3e-04 coming.

    Its response is a high-pass, eq. (12b)::

    Because the samples at negative indices are replaced by zeros rather than
    their true values, differencing leaves a boundary term: a polynomial of
    degree ``d-1`` in ``z_k^-1`` (Theorem 2). Those are the extra regressors.
    The ``m = 0`` term is omitted because a constant is already spanned by the
    transient polynomial, which is why eq. (21) sums from ``m = 1``.
    """

    def __init__(self, order: int = 1):
        if order < 1:
            raise ValueError(f"differencing order must be >= 1, got {order}")
        self.order = int(order)

    def __repr__(self):
        return f"Differencing(order={self.order})"

    def apply(self, y):
        y = np.asarray(y, dtype=float)
        for _ in range(self.order):
            y = np.diff(y, prepend=0.0)
        return y

    def frequency_response(self, k, N):
        z_inv = np.exp(-2j * np.pi * np.asarray(k) / N)
        return (1.0 - z_inv) ** self.order

    def extra_regressors(self, k, N):
        k = np.asarray(k)
        m = np.arange(1, self.order)                      # eq. (21): m = 1..d-1
        if m.size == 0:
            return np.zeros((k.size, 0), dtype=complex)
        return np.exp(-2j * np.pi * np.outer(k, m) / N)

    @property
    def n_extra_params(self):
        return max(self.order - 1, 0)

        """eq. (12c): the exact lambda_m, from the last ``d`` samples of ``y``.

        Not needed for estimation -- the gammas are fitted -- but it makes the

                for r in range(1, d - m + 1))
            for m in range(d)

Trend removal by a zero-phase response, applied by FFT.

    A subclass supplies :meth:`frequency_response` only; ``apply`` is then
    ``ifft(F * fft(y))``, which makes ``Y_d(k) = F(k) Y(k)`` hold exactly and

      record is not real. :func:`check_response` checks this.

      sharply from ``y[0]``, and the circular filter sees that jump as signal,
      so the lowest bins carry a residual the filter put there itself. There

    """

Subtract a centred moving average of length samples.

y_d(n) = y(n) - (1/L) * sum_{m=-M}^{M} y(n-m),   L = 2M+1

The response is one minus the Dirichlet kernel, which is real and symmetric because the window is centred::

F(k) = 1 - sin(pi k L / N) / (L sin(pi k / N))

length must be odd, so that the window has a true centre and the response carries no phase. Near DC F(k) ~ (L^2 - 1) (pi k / N)^2 / 6: a double zero, so the constant bin is annihilated and everything else is merely attenuated.

Choosing length: a boxcar is a poor filter and this is where it shows. Its response is the Dirichlet kernel, so F has sidelobes, overshoots above 1, and is not monotone. Checking |F| at the tone is therefore worthless -- MovingAverage(20001) on a 160000-sample record has |F| = 1.00005 at bin 8 and swings from 0.363 to 1.214 over the +-4 bins either side. Use :meth:band_response and judge by ripple.

y_d = (I - b (b^T b)^-1 b^T) y

with b the Legendre basis on the record, the same basis BLTVA uses for its trend block. Legendre rather than monomial because the monomial Vandermonde is hopeless beyond degree ~15 while Legendre stays usable.

This is the one strategy with no frequency response at all, and not for want of deriving it. That is not a loss, because BLTVA already does polynomial trend removal and does it better. The Nq drift block of eq. def select_differencing_order(y, fs, f_max, max_order=5):
    """Pick ``d`` by minimising the variance of the differenced series, eq. (11).

        d = argmin_{d >= 0} var(Delta^d y_bar(n))

    ``y_bar`` is ``y`` subsampled by ``floor(fs / (2*f_max))``, which the paper
    requires so that the series looks random to the criterion rather than
    oversampled and smooth. Differencing too few times leaves trend; too many
    amplifies the high-frequency end and the variance rises again, so the
    minimum is the balance point.

    Returns 0 when no differencing helps, meaning the record carries no trend
    worth removing.

    Caveat: the criterion assumes the record is "a trend plus a random time
    series", which the paper justifies by the random phases of the multisine.
    A strongly low-pass response breaks that assumption -- its variance is
    dominated by the lowest excited frequencies, which differencing attenuates
    -- so the rule can return ``d >= 1`` on a record with no trend at all.
    Treat the result as a starting point and check it against the spectrum
    rather than applying it blindly.
    """
    y = np.asarray(y, dtype=float)
    q = max(1, int(np.floor(fs / (2.0 * f_max))))
    series = y[::q]
    if series.size <= max_order + 1:
        raise ValueError(
            f"subsampling by {q} leaves only {series.size} samples, too few to "
            f"difference {max_order} times")

    variances = []
    for d in range(max_order + 1):
        if d:
            series = np.diff(series, prepend=0.0)
        # the first d samples carry the zero-padding step, not signal
        variances.append(float(np.var(series[d:])))
    return int(np.argmin(variances))

    regressors cannot absorb, relative to the signal, on a random record with
    a quadratic trend. A strategy that satisfies the contract returns ~1e-15;
    anything else is reporting a response that does not describe what it did,
    and an estimator built on it is biased with no warning.

    A constant column joins ``extra_regressors`` in the projection, because
    the estimator has one: eq. (21) omits the ``m = 0`` boundary term on the
    grounds that the transient polynomial already spans a constant, and the
    first column of ``legvander`` is exactly that. Leaving it out would fail
    ``Differencing(1)`` -- whose entire boundary term is that constant -- at
    7.8e-03, which is a gap in the check rather than in the class.

    Also reports whether the detrended record came back real, which requires
    ``F(k) = F(N-k)``.

    Returns
    -------
    dict with keys ``residual`` (the relative residual above), ``imaginary``
    (the largest imaginary part the response would have produced) and
    ``exact`` (whether ``residual`` is at round-off).
    """
    rng = np.random.default_rng(seed)
    t = np.linspace(0.0, 1.0, N)
    y = rng.normal(size=N) + 3.0 * t ** 2 + 0.5 * t

    k = np.arange(N)
    F = strategy.frequency_response(k, N)
    target = F * np.fft.fft(y)
    residual = np.fft.fft(strategy.apply(y)) - target

    # what the estimator can legitimately absorb: the boundary block, plus the
    # constant that eq. (21) leaves to the transient polynomial
    absorbable = np.hstack([np.ones((N, 1), dtype=complex),
                            strategy.extra_regressors(k, N)])
    coefficients, *_ = np.linalg.lstsq(absorbable, residual, rcond=None)
    residual = residual - absorbable @ coefficients

    scale = np.max(np.abs(target))
    relative = float(np.max(np.abs(residual)) / scale) if scale else float("inf")
    imaginary = float(np.max(np.abs(np.fft.ifft(F * np.fft.fft(y)).imag)))
    return {"residual": relative, "imaginary": imaginary,
            "exact": relative < 1e-10}

Record consistency check¶

consistency ¶

Does the record agree with the numbers that describe it?

Every estimator here is handed a sampling time, a list of excited frequencies and -- for the windowed ones -- a multisine period, and every one of them assumes those numbers describe the record they were given. Four quantities are tied together by one equation,

.. math:: N = P \, T_p \, f_s

the samples in the record, the multisine periods it holds, the period and the sampling rate. Get one wrong and almost nothing refuses to run. The excited tones stop landing on DFT bin centres, the leakage that a periodic record was designed to avoid comes back, and every estimator in the package reports it as impedance: STFT sees a window that is not a whole number of periods and calls the leakage time variation, BLA's bin classes point at the wrong bins, BLTVA fits its Legendre polynomials to a record whose period it has wrong.

The three error modes, and what separates them

The arithmetic alone cannot say which number is wrong -- only that they disagree. The signal can, because a wrong fs or Tp moves the spectral lines while a wrong N only smears them:

=========================  ===========================================
what is wrong              what the spectrum does
=========================  ===========================================
``N`` (record truncated    the lines stay where they are and the
mid-period)                *nominal* bin positions slide off the grid
                           instead, in proportion to the harmonic
                           number. Measured and nominal still agree
                           with each other; each tone grows a leakage
                           skirt because its bin is no longer a bin.
``fs`` (card clock, or a   every line moves, by an amount
typo)                      *proportional to its harmonic number*,
                           away from a nominal position that is off
                           the grid as well
``Tp`` (generator period   the same as a wrong ``fs``: of the two only
is not the one designed)   the product ``T_p f_s`` is observable from
                           one record, so the report gives both
                           readings and you choose
``P`` (miscounted)         nothing -- the record is what it is. The
                           count is checked against the other three,
                           and against how many whole periods the
                           signal turns out to hold
=========================  ===========================================

So the measurement to make is the fractional bin position of each tone, :math:k_i, against its nominal position :math:h_i N T_s / T_p. Fitting

.. math:: k_i^{\rm meas} = (1 + e) \, k_i^{\rm nom}

gives one number, the relative timebase error :math:e, and the three readings of it are

.. math:: f_s^{\rm true} = f_s / (1+e), \quad T_p^{\rm true} = T_p / (1+e), \quad P^{\rm true} = (1+e) P

A record whose only fault is a truncated tail gives :math:e \ne 0 as well, and is told apart by :math:P^{\rm true} landing on a whole number while :math:f_s^{\rm true} comes out at an implausible value -- which is why the report prints all three and leaves the choice to the person who knows what the instrument was set to.

:math:e is measured twice, by two routes that fail differently:

  • from the whole-record spectrum, by sub-bin interpolation of each peak (Jacobsen's estimator). Precise, and blind to nothing except a tone buried in noise.
  • from the phase of each tone period by period. If the period is right the phase is constant across periods; if it is off by a fraction of a sample the phase advances linearly, at a rate proportional to the harmonic number. This one also responds to the cell genuinely drifting -- but drift is not proportional to the harmonic number, and that is the discriminant.

They agree on a timing error and part company on a drifting cell, so the pair says more than either alone.

What else this looks at

The same pass over the spectrum answers the neighbouring questions cheaply: whether every listed tone is actually present (a tone with no line above the local noise floor was not excited, or is not at the frequency it is listed at), whether anything not on the list is comparable to the tones (mains pickup, a forgotten harmonic, strong distortion), whether the harmonic numbers are integers at all -- :meth:~deistools.processing.mfa.MultiFrequencyAnalysis.run_bla, run_bltva and run_lia all round f / f.min() and will quietly use the rounded value -- and whether the lowest listed tone really is the fundamental, which those same three functions assume.

Nothing here raises on a bad record; reporting is the whole job. The one exception is a sampling time that is not a positive number, which leaves nothing to report on.

class ConsistencyReport:
    """Everything the check measured, and what it concluded.

    The headline is :attr:`worst` and :attr:`findings`; ``print(report)``
    lays out the numbers in the order you need them to decide which of the
    four is wrong. The arrays are kept so that
    :func:`visualize_consistency` can draw them without measuring twice.
    """

    # --- the metadata, as handed in and as implied -------------------------
    n_samples: int
    sampling_time: float
    sampling_frequency: float
    duration: float
    period_claimed: float | None
    period: float                   #: the one the arithmetic below uses
    base_frequency: float
    samples_per_period: float
    periods_in_record: float
    n_periods_claimed: int | None
    frequencies: np.ndarray
    harmonics: np.ndarray           #: ``frequencies * period``, unrounded
    subdivision: int                #: 1 if the lowest tone is the fundamental

    # --- bin positions ----------------------------------------------------
    bin_nominal: np.ndarray         #: fractional, ``f * N * Ts``
    bin_measured: np.ndarray        #: fractional, from the spectrum
    bin_offset: np.ndarray          #: measured minus nominal
    measured_on: np.ndarray         #: 'V' or 'I', whichever tone was cleaner
    at_search_edge: np.ndarray      #: peak hit the window edge: unreliable

    # --- the timebase error, both ways ------------------------------------
    timebase_error: float           #: e, from the whole-record spectrum
    timebase_scatter: float         #: rms residual of that fit, in bins
    timebase_error_folded: float    #: e, from the period-by-period phase
    phase_drift: np.ndarray         #: (n_periods, n_tones) unwrapped, rad
    phase_slope: np.ndarray         #: rad per period, per tone

    # --- levels -----------------------------------------------------------
    amplitude_voltage: np.ndarray
    amplitude_current: np.ndarray
    snr_db_voltage: np.ndarray
    snr_db_current: np.ndarray
    stray_lines: list              #: (frequency, amplitude, fraction, label)

    # --- for the figure ---------------------------------------------------
    bin_frequencies: np.ndarray = field(repr=False, default=None)
    magnitude_voltage: np.ndarray = field(repr=False, default=None)
    magnitude_current: np.ndarray = field(repr=False, default=None)
    voltage: np.ndarray = field(repr=False, default=None)
    current: np.ndarray = field(repr=False, default=None)

    findings: list = field(default_factory=list)

    # ----------------------------------------------------------------------
    @property
    def worst(self) -> str:
        """The highest severity reached, ``'ok'`` if nothing was noticed."""
        if not self.findings:
            return "ok"
        return max(self.findings, key=lambda f: LEVELS.index(f.level)).level

    @property
    def ok(self) -> bool:
        """True when nothing worse than ``info`` came up."""
        return LEVELS.index(self.worst) <= LEVELS.index("info")

    def __getitem__(self, code):
        """The findings with a given code, as a list."""
        return [f for f in self.findings if f.code == code]

    def worst_offset(self):
        """Largest measured-minus-nominal offset, over the trustworthy tones.

        A tone whose peak was found at the edge of its search window is left
        out: that line may not be the one it was looking for, and one mistyped
        frequency should not be allowed to set the headline number.
        """
        trusted = np.isfinite(self.bin_offset) & ~self.at_search_edge
        if not np.any(trusted):
            return np.nan
        return float(np.max(np.abs(self.bin_offset[trusted])))

    def implied(self):
        """The three readings of the measured timebase error.

        Returns ``(fs, period, n_periods)``: what each would have to be for
        the tones to sit where the spectrum says they do, on the assumption
        that the other two are right.
        """
        scale = 1.0 + self.timebase_error
        return (self.sampling_frequency / scale,
                self.period / scale,
                self.periods_in_record * scale)

    def __str__(self):
        return self.summary()

    def summary(self):
        """The numbers, in the order you need them to place the blame."""
        spp, P = self.samples_per_period, self.periods_in_record
        d_spp = spp - round(spp) if np.isfinite(spp) else np.nan
        d_P = P - round(P) if np.isfinite(P) else np.nan
        if self.period_claimed is None:

        else:

        if self.n_periods_claimed is not None:

        else:

        lines = [f"Multi-frequency record check -- {self.worst.upper()}", ""]

            f"          (Ts = {self.sampling_time:.6g} s)",
            f"  duration            {self.duration:.10g} s",
            f"  multisine period    {self.period:.10g} s{claimed}",
            f"  fundamental         {self.base_frequency:.10g} Hz",
            f"  samples per period  {spp:.6f}"
            f"     {_exactness(d_spp, 'sample')}",
            f"  periods in record   {P:.6f}"
            f"     {_exactness(d_P, 'period')}",
            f"  N = P x Tp x fs     {self.n_samples} = {P_int}"
            f" x {self.period:.10g} s x {self.sampling_frequency:.10g} Hz"
            f" = {P_int * self.period * self.sampling_frequency:.10g}",
            "",
            f"  tones               {self.frequencies.size} from"
            f" {self.frequencies.min():.6g} to {self.frequencies.max():.6g} Hz",
            f"  harmonic numbers    {self.harmonics.min():.6g} ..",

        lines[-1] += (f" {self.harmonics.max():.6g}, integer to"
                      f" {np.max(np.abs(self.harmonics - np.round(self.harmonics))):.2g}")
        residual = np.max(np.abs(self.bin_nominal - np.round(self.bin_nominal)))
        lines.append(f"  nominal bins        {np.min(self.bin_nominal):.6g} .."
                     f" {np.max(self.bin_nominal):.6g}, on grid to"

        lines += ["", "  measured from the signals"]

            ]
        else:
            lines.append("    timebase error    not measurable")

            if finite.size:
                lines.append(f"    tone SNR {name}        {finite.min():.1f} .."
                             f" {finite.max():.1f} dB, median"
                             f" {np.median(finite):.1f} dB")
            else:
                lines.append(f"    tone SNR {name}        noiseless")
        if self.stray_lines:
            lines.append(f"    stray lines       {len(self.stray_lines)}:")
            for f_hz, amp, frac, label in self.stray_lines:
                lines.append(f"                        {f_hz:>12.6g} Hz"
                             f"  {100 * frac:6.1f}% of the tones  {label}")
        else:
            lines.append("    stray lines       none above"
                         f" {100 * STRAY_FRACTION:g}% of the tones")

        lines.append("")
        if self.findings:
            # The verdict first, the evidence after: several of the findings
            # below offer alternatives that only the verdict chooses between.
            headline = [f for f in self.findings
                        if f.code in ("diagnosis", "off_grid_scatter")]
            lines += [f"  {f}" for f in headline]
            lines += [f"  {f}" for f in self.findings if f not in headline]
        else:
            lines.append("  nothing to report")
        return "\n".join(lines)

    Returns
    -------
    :class:`ConsistencyReport`
        ``print(report)`` for the numbers, ``report.findings`` for the
        verdicts, ``report.ok`` for a single boolean, and
        :func:`visualize_consistency` for the figure.

    Notes
    -----
    Cheap enough to run before every estimation: two real FFTs of the record
    and one of each period.
    """
    findings = []
    add = lambda level, code, message: findings.append(Finding(level, code, message))

    sampling_time = float(sampling_time)
    if not np.isfinite(sampling_time) or sampling_time <= 0:
        raise ValueError(f"sampling_time must be a positive number, got "
                         f"{sampling_time!r}; there is nothing to check "
                         "a record against without it")

    voltage = np.asarray(voltage, dtype=float).ravel()
    current = np.asarray(current, dtype=float).ravel()
    frequencies = np.asarray(frequencies, dtype=float).ravel()

    # --- the arrays, before anything is measured from them -----------------
    if voltage.size != current.size:
        shortest = min(voltage.size, current.size)
        add("fail", "arrays",
            f"voltage has {voltage.size} samples and current {current.size}. "
            f"They are two channels of one measurement and must have the same "
            f"length; the first {shortest} of each are checked below, but one "
            f"of the two files is not the one you think it is.")
        voltage, current = voltage[:shortest], current[:shortest]

    cleaned = []
    for name, signal in (("voltage", voltage), ("current", current)):
        finite = np.isfinite(signal)
        bad = int(signal.size - np.count_nonzero(finite))
        if bad:
            add("fail", "not_finite",
                f"{name} has {bad} non-finite samples ({100 * bad / signal.size:.2g}% "
                f"of the record). One NaN makes the whole DFT NaN, so every "
                f"estimator returns NaN at every frequency. For the checks "
                f"below they are replaced by the channel mean, in a copy -- "
                f"the array you passed is not touched.")
            signal = signal.copy()
            signal[~finite] = np.mean(signal[finite]) if np.any(finite) else 0.0
        cleaned.append(signal)
    voltage, current = cleaned

    n_samples = int(voltage.size)
    sampling_frequency = 1.0 / sampling_time
    duration = n_samples * sampling_time
    if n_samples < 16:
        add("fail", "too_short",
            f"{n_samples} samples is too short to check anything.")

    if frequencies.size == 0 or np.any(frequencies <= 0):
        add("fail", "frequencies",
            "the frequency list must hold positive frequencies in Hz; "
            f"got {frequencies}")
        frequencies = frequencies[frequencies > 0] if frequencies.size else frequencies
    if frequencies.size and np.any(np.diff(frequencies) <= 0):
        add("warn", "frequency_order",
            "the frequency list is not strictly increasing. Every estimator "
            "returns its rows in the order of this list, so the impedance "
            "rows will be in that same scrambled order.")

    nyquist = 0.5 * sampling_frequency
    if frequencies.size and frequencies.max() >= nyquist:
        above = frequencies[frequencies >= nyquist]
        add("fail", "nyquist",
            f"{above.size} tone(s) at or above the Nyquist frequency "
            f"{nyquist:.6g} Hz (worst {above.max():.6g} Hz). These are "
            f"aliased: they appear at {sampling_frequency - above.max():.6g} Hz "
            f"and the impedance reported for them is another frequency's.")
    elif frequencies.size and frequencies.max() > 0.4 * sampling_frequency:
        add("info", "nyquist",
            f"the top tone {frequencies.max():.6g} Hz is at "
            f"{100 * frequencies.max() / nyquist:.0f}% of Nyquist, where an "
            f"anti-alias filter has amplitude and phase of its own. It divides "
            f"out of V/I only if both channels went through the same one.")

    # --- the fundamental: is the lowest tone harmonic 1? -------------------
    if frequencies.size:
        base_inferred, subdivision = _infer_fundamental(frequencies)
    else:
        base_inferred, subdivision = np.nan, 1
    if subdivision > 1:
        add("warn", "fundamental",
            f"the listed tones are harmonics of {base_inferred:.6g} Hz, not of "
            f"the lowest listed tone {frequencies.min():.6g} Hz: the lowest one "
            f"is harmonic {subdivision}, not 1. run_bla, run_bltva and run_lia "
            f"all take the harmonic numbers as round(f / f.min()) and will be "
            f"wrong about every one of them. Pass period={1 / base_inferred:.10g} "
            f"and treat their harmonic grids as suspect.")

    # --- the four numbers --------------------------------------------------
    period_claimed = None if period is None else float(period)
    if period_claimed is not None:
        period_used = period_claimed
        if frequencies.size and np.isfinite(base_inferred):
            implied = 1.0 / base_inferred
            ratio = period_used / implied
            if abs(ratio - 1) > 1e-6 and abs(ratio - round(ratio)) > 1e-6:
                add("warn", "period_vs_tones",
                    f"period={period_used:.10g} s, but the tone list is a "
                    f"harmonic grid of {implied:.10g} s. The two disagree by a "
                    f"factor {ratio:.6g}, which is not a whole number of "
                    f"periods either way, so at least one of them is wrong.")
    elif frequencies.size and np.isfinite(base_inferred):
        period_used = 1.0 / base_inferred
        add("info", "period",
            f"no period given, so the tone list was used: it is a harmonic "
            f"grid of {period_used:.10g} s. That makes the period check "
            f"self-referential -- pass the period you set on the generator to "
            f"get a real one.")
    else:
        period_used = np.nan

    base_frequency = 1.0 / period_used if np.isfinite(period_used) else np.nan
    harmonics = frequencies * period_used
    samples_per_period = period_used / sampling_time
    periods_in_record = duration / period_used

    # --- the triangle N = P Tp fs ------------------------------------------
    bin_nominal = frequencies * n_samples * sampling_time
    grid_residual = (float(np.max(np.abs(bin_nominal - np.round(bin_nominal))))
                     if frequencies.size else np.nan)

    if np.isfinite(samples_per_period):
        off = samples_per_period - round(samples_per_period)
        if abs(off) > 1e-9:
            spp_int = int(round(samples_per_period))
            add("fail", "samples_per_period",
                f"one multisine period is {samples_per_period:.6f} samples, not "
                f"a whole number. Every windowed estimator turns the period "
                f"into int(round(period / sampling_time)) = {spp_int} samples, "
                f"so each window is {off:+.4g} samples wrong and the error "
                f"accumulates down the record. For a whole number, either "
                f"fs = {round(samples_per_period) / period_used:.10g} Hz at this "
                f"period, or period = {spp_int * sampling_time:.10g} s at this fs.")

    if np.isfinite(periods_in_record):
        whole = int(round(periods_in_record))
        off = periods_in_record - whole
        if abs(off) > 1e-9 and whole >= 1:
            spp_int = max(int(round(samples_per_period)), 1)
            complete = int(np.floor(periods_in_record + 1e-9))
            past = n_samples - complete * spp_int
            short = (complete + 1) * spp_int - n_samples
            add("fail", "whole_periods",
                f"the record holds {periods_in_record:.6f} multisine periods, "
                f"not a whole number: it runs {past} samples past {complete} "
                f"whole periods, and stops {short} samples short of "
                f"{complete + 1}. The DFT "
                f"of a record cut mid-period leaks, and the leakage is exactly "
                f"what STFT, DMFA and BLTVA report as time variation; "
                f"bltva() refuses the record outright (N % P). Three ways out, "
                f"and only you know which number is the wrong one: keep the "
                f"first {complete * spp_int} samples of {n_samples}, which is "
                f"{complete} whole periods (cut_signal_tail); or fs is really "
                f"{n_samples / (whole * period_used):.10g} Hz; or the period is "
                f"really {n_samples / (whole * sampling_frequency):.10g} s. The "
                f"measured timebase error below says which.")

    if n_periods is not None and np.isfinite(periods_in_record):
        if abs(periods_in_record - n_periods) > 1e-6:
            add("fail", "n_periods",
                f"you say the record holds {n_periods} periods; N, period and fs "
                f"say {periods_in_record:.6f}. BLTVA reads the excited tones at "
                f"bins P*h and treats every bin with k % P == 0 as a multisine "
                f"harmonic, so a wrong P does not degrade the estimate, it reads "
                f"a different set of bins. run_bla's periods_per_window is "
                f"affected the same way.")

    if frequencies.size and np.isfinite(grid_residual):
        if grid_residual > ON_BIN_TOLERANCE:
            worst = int(np.argmax(np.abs(bin_nominal - np.round(bin_nominal))))
            add("fail", "on_grid",
                f"{frequencies[worst]:.6g} Hz sits {grid_residual:.4g} bins from "
                f"a bin centre (bin spacing {1 / duration:.6g} Hz). "
                f"compute_freq_indexes raises on anything past "
                f"{ON_BIN_TOLERANCE} bins, so run_fft_eis and run_dmfa will not "
                f"start; what a tone off a bin centre costs is leakage into its "
                f"neighbours, which is the same error the windowed methods make "
                f"silently.")
        elif grid_residual > 1e-6:
            add("info", "on_grid",
                f"the tones are within {grid_residual:.2g} bins of a centre -- "
                f"close enough for compute_freq_indexes, far enough to leak a "
                f"little. Exact is reachable: it needs f * N * sampling_time to "
                f"be whole for every tone.")

    if frequencies.size > 1:
        rounded = np.round(bin_nominal).astype(int)
        gaps = np.diff(rounded)
        if np.any(gaps == 0):
            share = frequencies[:-1][gaps == 0]
            add("fail", "bin_collision",
                f"{share.size} pair(s) of tones land on the same DFT bin "
                f"(first at {share[0]:.6g} Hz). The impedance reported for both "
                f"is the same number; the record is too short to separate them, "
                f"and needs {1 / np.min(np.diff(frequencies)):.6g} s to do so.")
        elif np.any(gaps == 1):
            add("warn", "bin_collision",
                f"{int(np.count_nonzero(gaps == 1))} pair(s) of tones land on "
                f"adjacent DFT bins. Nothing can be read about either one's "
                f"neighbourhood -- no leakage check, no local noise floor, and "
                f"search_freq_indexes has no room to search.")

    harmonic_residual = (float(np.max(np.abs(harmonics - np.round(harmonics))))
                         if frequencies.size and np.isfinite(period_used) else np.nan)
    if np.isfinite(harmonic_residual) and harmonic_residual > HARMONIC_TOLERANCE:
        worst = int(np.argmax(np.abs(harmonics - np.round(harmonics))))
        add("warn", "harmonics",
            f"harmonic number {harmonics[worst]:.6g} at {frequencies[worst]:.6g} Hz "
            f"is not an integer ({harmonic_residual:.3g} off). run_bla, "
            f"run_bltva and run_lia round it to {round(harmonics[worst])}, and "
            f"then work at a frequency you did not excite.")

    # --- what the signals themselves say -----------------------------------
    spectrum_voltage = np.fft.rfft(voltage) / n_samples
    spectrum_current = np.fft.rfft(current) / n_samples
    magnitude_voltage = np.abs(spectrum_voltage)
    magnitude_current = np.abs(spectrum_current)
    bin_frequencies = np.fft.rfftfreq(n_samples, sampling_time)
    n_bins = bin_frequencies.size

    tiny = np.finfo(float).tiny
    floor_voltage_all = max(float(np.median(magnitude_voltage[1:])), tiny)
    floor_current_all = max(float(np.median(magnitude_current[1:])), tiny)

    if frequencies.size and n_bins > 4:
        centres = np.clip(np.round(bin_nominal).astype(int), 1, n_bins - 2)
        # Which channel shows each tone more clearly. Volts and amps cannot be
        # compared, so the comparison is each channel's line against its own
        # broadband level, which is a ratio and has no units.
        clarity_voltage = magnitude_voltage[centres] / floor_voltage_all
        clarity_current = magnitude_current[centres] / floor_current_all
        use_voltage = clarity_voltage > clarity_current

        halfwidth = _search_halfwidth(centres, n_bins)
        position_voltage, edge_voltage = _measure_peaks(
            spectrum_voltage, centres, halfwidth)
        position_current, edge_current = _measure_peaks(
            spectrum_current, centres, halfwidth)
        bin_measured = np.where(use_voltage, position_voltage, position_current)
        at_search_edge = np.where(use_voltage, edge_voltage, edge_current)
        measured_on = np.where(use_voltage, "V", "I")
        weight = np.clip(np.where(use_voltage, clarity_voltage, clarity_current),
                         0.0, 1e4)

        timebase_error, timebase_scatter = _fit_timebase(
            bin_nominal, bin_measured, np.where(at_search_edge, 0.0, weight))

        # A large error means the first pass was searching off-centre. Recentre
        # on what it found and measure again, narrowly: a wide window around
        # the right place is how a neighbouring line gets picked up instead.
        if (np.isfinite(timebase_error)
                and abs(timebase_error) * np.max(bin_nominal) > 1.0):
            moved_centres = np.clip(
                np.round(bin_nominal * (1.0 + timebase_error)).astype(int),
                1, n_bins - 2)
            narrow = np.clip(_search_halfwidth(moved_centres, n_bins), 1, 4)
            position_voltage, edge_voltage = _measure_peaks(
                spectrum_voltage, moved_centres, narrow)
            position_current, edge_current = _measure_peaks(
                spectrum_current, moved_centres, narrow)
            bin_measured = np.where(use_voltage, position_voltage, position_current)
            at_search_edge = np.where(use_voltage, edge_voltage, edge_current)
            timebase_error, timebase_scatter = _fit_timebase(
                bin_nominal, bin_measured, np.where(at_search_edge, 0.0, weight))

        peak_voltage = np.clip(np.round(position_voltage).astype(int), 0, n_bins - 1)
        peak_current = np.clip(np.round(position_current).astype(int), 0, n_bins - 1)
        excited = np.zeros(n_bins, dtype=bool)
        excited[:3] = True
        for k in np.round(bin_measured).astype(int):
            excited[max(int(k) - 3, 0):int(k) + 4] = True

        floor_voltage = _noise_floor(magnitude_voltage, peak_voltage, excited)
        floor_current = _noise_floor(magnitude_current, peak_current, excited)
        amplitude_voltage = 2.0 * magnitude_voltage[peak_voltage]
        amplitude_current = 2.0 * magnitude_current[peak_current]
        snr_db_voltage = _snr_db(magnitude_voltage[peak_voltage], floor_voltage)
        snr_db_current = _snr_db(magnitude_current[peak_current], floor_current)

        stray_lines = []
        for tag, magnitude, peaks in (("in the voltage", magnitude_voltage, peak_voltage),
                                      ("in the current", magnitude_current, peak_current)):
            reference = float(np.median(magnitude[peaks]))
            if reference <= 0:
                continue
            for f_hz, amp, frac, label in _stray_lines(
                    magnitude, bin_frequencies, excited, reference,
                    base_frequency, fraction=stray_fraction, limit=4):
                stray_lines.append((f_hz, amp, frac, f"{label}, {tag}"))
        stray_lines.sort()
    else:
        bin_measured = np.full(frequencies.shape, np.nan)
        at_search_edge = np.zeros(frequencies.shape, dtype=bool)
        measured_on = np.full(frequencies.shape, "-", dtype="<U1")
        timebase_error = timebase_scatter = np.nan
        amplitude_voltage = np.full(frequencies.shape, np.nan)
        amplitude_current = np.full(frequencies.shape, np.nan)
        snr_db_voltage = np.full(frequencies.shape, np.nan)
        snr_db_current = np.full(frequencies.shape, np.nan)
        stray_lines = []
        use_voltage = np.zeros(frequencies.shape, dtype=bool)

    bin_offset = bin_measured - bin_nominal

    # --- the same error, measured again period by period --------------------
    # On the current, because the current is the excitation (every estimator
    # here is called with the voltage as the response). Its phase moves with
    # the timebase and with nothing else, while the voltage's also moves when
    # the cell drifts -- which is why the two routes below can disagree.
    phase_drift = np.zeros((0, frequencies.size))
    phase_slope = np.full(frequencies.shape, np.nan)
    timebase_error_folded = np.nan
    if (frequencies.size and np.isfinite(samples_per_period)
            and samples_per_period >= 8 and periods_in_record >= 3):
        complete = int(np.floor(periods_in_record + 1e-9))
        phase_drift, phase_slope = _folded_phase(
            current, samples_per_period, complete, harmonics)
        whole_harmonics = np.round(harmonics)
        with np.errstate(divide="ignore", invalid="ignore"):
            per_tone = phase_slope / (2.0 * np.pi * whole_harmonics)
        # A step of more than pi per period is aliased by the unwrap, so those
        # tones are dropped rather than believed.
        usable = (np.isfinite(per_tone) & (np.abs(phase_slope) < np.pi)
                  & (whole_harmonics >= 1))
        if np.any(usable):
            timebase_error_folded = float(np.median(per_tone[usable]))

    # --- the verdict --------------------------------------------------------
    whole_record = (np.isfinite(periods_in_record)
                    and abs(periods_in_record - round(periods_in_record)) < 1e-6)
    # Only the tones the fit was allowed to use. A line found at the edge of
    # its search window may be a different line altogether, and letting one
    # of those set the headline number is how a single mistyped frequency
    # comes to look like a broken clock.
    trusted = np.isfinite(bin_offset) & ~at_search_edge
    moved = float(np.max(np.abs(bin_offset[trusted]))) if np.any(trusted) else np.nan
    if np.isfinite(timebase_error):
        implied_fs = sampling_frequency / (1.0 + timebase_error)
        implied_period = period_used / (1.0 + timebase_error)
        implied_periods = periods_in_record * (1.0 + timebase_error)
        implied_whole = (np.isfinite(implied_periods)
                         and abs(implied_periods - round(implied_periods)) < 2e-3)
        significant = np.isfinite(moved) and moved > ON_BIN_TOLERANCE
        common_scale = timebase_scatter <= max(0.05, 0.3 * moved)
        readings = (f"fs = {implied_fs:.10g} Hz, or the period = "
                    f"{implied_period:.10g} s, or the record holding "
                    f"{implied_periods:.6f} periods")

        if significant and not common_scale:
            add("fail", "off_grid_scatter",
                f"the tones are off their bins by up to {moved:.3g} bins, and "
                f"not by a common factor: the scatter around the best "
                f"proportional fit is {timebase_scatter:.3g} bins against a fit "
                f"of {abs(timebase_error) * np.max(bin_nominal):.3g}. No "
                f"sampling rate, period or record length does that. The tone "
                f"list itself is wrong, or the generator is not producing a "
                f"harmonic multisine. search_freq_indexes will find the lines; "
                f"nothing will make them leakage-free.")
        elif significant and implied_whole and not whole_record:
            add("fail", "diagnosis",
                f"the record length is right and the sampling rate or the "
                f"period is wrong. The tones sit {timebase_error:+.4g} of their "
                f"frequency away from where the metadata puts them, and at that "
                f"correction the record holds {round(implied_periods)} whole "
                f"periods exactly. So: {readings}. Which of the two it is, one "
                f"record cannot say -- only the product Tp*fs is observable -- "
                f"so take it from whichever of the generator and the card you "
                f"trust less.")
        elif significant:
            add("fail", "diagnosis",
                f"the tones are {timebase_error:+.4g} of their frequency away "
                f"from where the metadata puts them (up to {moved:.3g} bins at "
                f"the top tone), which reads as {readings}. That corrected count "
                f"is not a whole number either, so the record length is wrong as "
                f"well as the rate or the period.")
        elif not whole_record:
            add("fail", "diagnosis",
                f"the sampling rate and the period are right and the record "
                f"length is wrong. Every tone is within {moved:.2g} bins of "
                f"where fs and the period put it (timebase error "
                f"{timebase_error:+.2g}, far too small to explain "
                f"{periods_in_record:.6f} periods), so nothing is wrong with the "
                f"timebase: the record simply does not end on a period boundary. "
                f"Trim it.")
        elif grid_residual > ON_BIN_TOLERANCE:
            add("warn", "diagnosis",
                f"N, P, Tp and fs agree with each other and with the signals -- "
                f"{periods_in_record:.0f} whole periods, timebase error "
                f"{timebase_error:+.2g} -- and it is the frequency list that "
                f"does not fit the grid those four define, by up to "
                f"{grid_residual:.3g} bins. The tones named above are the ones "
                f"to correct; the metadata is not the problem.")
        else:
            add("ok", "diagnosis",
                f"N, P, Tp and fs agree with each other and with the signals: "
                f"{periods_in_record:.0f} whole periods, every tone on a bin "
                f"centre to {grid_residual:.1g} bins, and the measured timebase "
                f"error is {timebase_error:+.2g} ({abs(timebase_error) * np.max(bin_nominal):.2g} "
                f"bins at the top tone).")

        if (np.isfinite(timebase_error_folded)
                and abs(timebase_error_folded - timebase_error)
                > max(5e-6, 3 * abs(timebase_error))):
            add("info", "phase_drift",
                f"the two measurements of the timebase error disagree: "
                f"{timebase_error:+.3g} from the whole-record spectrum, "
                f"{timebase_error_folded:+.3g} from the phase walk period to "
                f"period. They are sensitive to different things, which is why "
                f"both are here: the first compares the lines against the "
                f"frequency list and is blind to the period, the second cuts "
                f"the record into periods and so feels the period as well. "
                f"Three things separate them -- a period that is wrong while "
                f"the frequency list is right, a cell that is drifting (whose "
                f"phase also walks, but not in proportion to the harmonic "
                f"number), or an actual clock error. The last panel of "
                f"visualize_consistency tells them apart: a slope proportional "
                f"to h is timing.")

    # --- is every listed tone actually there? -------------------------------
    for name, snr in (("voltage", snr_db_voltage), ("current", snr_db_current)):
        weak = np.isfinite(snr) & (snr < snr_warn_db)
        if np.any(weak):
            worst = int(np.argmin(np.where(weak, snr, np.inf)))
            add("warn", "tone_missing",
                f"{int(np.count_nonzero(weak))} of {frequencies.size} tones are "
                f"less than {snr_warn_db:g} dB above the local noise floor in "
                f"the {name} (worst {frequencies[worst]:.6g} Hz at "
                f"{snr[worst]:.1f} dB). Either the tone was not excited, or it "
                f"is not at the frequency it is listed at; the impedance "
                f"reported there is a ratio of two noise samples, and it will "
                f"look like a wildly time-varying cell.")
    if np.any(at_search_edge):
        add("info", "search_edge",
            f"{int(np.count_nonzero(at_search_edge))} tone(s) peaked at the edge "
            f"of their search window, so the line found may not be the right "
            f"one and those positions are excluded from the timebase fit.")

    if stray_lines:
        biggest = max(stray_lines, key=lambda row: row[2])
        add("warn" if biggest[2] > 0.2 else "info", "stray_line",
            f"{len(stray_lines)} line(s) that are not on the tone list reach "
            f"{100 * biggest[2]:.0f}% of the median tone ({biggest[0]:.6g} Hz, "
            f"{biggest[3]}). A harmonic of the fundamental is distortion or a "
            f"tone left off the list; anything else is pickup, and it biases "
            f"the bins it lands near.")

    # --- the two faults that make all of the above meaningless --------------
    for name, signal in (("voltage", voltage), ("current", current)):
        span = float(np.ptp(signal))
        if span <= 0:
            add("fail", "constant",
                f"the {name} does not change over the whole record.")
            continue
        at_rail = (np.count_nonzero(np.abs(signal - signal.max()) <= 1e-9 * span)
                   + np.count_nonzero(np.abs(signal - signal.min()) <= 1e-9 * span))
        if at_rail > max(8, 0.001 * n_samples):
            add("warn", "clipping",
                f"{at_rail} samples of the {name} ({100 * at_rail / n_samples:.2g}%) "
                f"sit exactly at the extreme value: the channel is clipping, or "
                f"the range was set too small. Clipping is a nonlinearity, so "
                f"the harmonics it generates appear as distortion and, on an "
                f"odd-harmonic grid, partly on the excited bins themselves.")

    if np.any(np.isfinite(amplitude_voltage)) and n_samples > 2:
        index = np.arange(n_samples, dtype=float)
        slope = np.polyfit(index, voltage, 1)[0]
        trend_span = abs(slope) * (n_samples - 1)
        # The median tone, not the sum: a trend this size leaks into the
        # lowest bins and inflates the tones there, so a sum would partly
        # measure the drift it is being compared against.
        typical = float(np.nanmedian(amplitude_voltage))
        periods = periods_in_record if np.isfinite(periods_in_record) else 1.0
        per_period = trend_span / max(periods, 1.0)
        if typical > 0 and per_period > typical:
            add("info", "drift",
                f"the voltage trends {trend_span:.4g} V across the record, "
                f"{per_period:.4g} V within one multisine period, against a "
                f"typical tone amplitude of {typical:.4g} V -- a factor "
                f"{per_period / typical:.3g}. That is the cell doing something "
                f"besides answering the excitation, which is what this package "
                f"is for; it is reported because a one-period window sees that "
                f"trend as leakage into the lowest tones. See "
                f"deistools.processing.detrending, and prefer run_bltva, which "
                f"models the trend, over run_stft_eis, which does not.")

    def run_bla(self, period, *, periods_per_window=4, n_local=30):
        """Per-burst impedance with the error attributed to its source.

        The short-time Fourier estimate, plus what the bins it discards say
        about *why* it is wrong: measurement noise, nonlinear distortion, or
        the cell changing while the burst was open.

        Parameters
        ----------
        period : float
            One multisine period in seconds.
        periods_per_window : int
            Multisine periods per burst. **At least 2**: at one period every
            bin of the burst is a harmonic of the multisine, so noise and
            distortion land in the same places. The uncertainty is paid for
            in time resolution.
        n_local : int
            Bins averaged for each level at each tone.

        Returns

            One entry per burst, stamped at the burst midpoint.

        Notes

        non-harmonic bins carry the time-variation skirt as well as the

    def run_goertzel(self, period):
        """Impedance per block, evaluated with the Goertzel recurrence.

        Computes the same quantity as :meth:`run_stft_eis` -- the record cut
        into blocks of ``period`` seconds, one spectrum each -- but evaluates
        only the excited bins, by a second-order recurrence instead of a
        transform. The two agree to about 1e-10.

        On a record of this size it is the slower of the two, because an FFT
        gives every bin for ``N*log2(N)`` operations while Goertzel costs
        ``N`` per bin: :func:`goertzel_cost_ratio` reports the crossover. It
        earns its place as an independent check on the STFT path, and because
        its recurrence is the one that also runs on a live stream.

        Returns
        -------
        (impedance, time) : ndarray, ndarray
        """
        return goertzel_eis(self.voltage, self.current, self.frequencies,
                            period, self.sampling_time)

    def goertzel_cost_ratio(self, period):
        """Goertzel operations divided by FFT operations; below 1 favours Goertzel."""
        return cost_ratio(np.size(self.frequencies),
                          int(round(period / self.sampling_time)))

    def run_lia(self, n_periods=1, *, base_frequency=None, window="boxcar",
                method="mix", decimate=None, stride=None):
        """Digital lock-in estimate of Z(f,t) at every excited frequency.

        Each tone is mixed down with a cosine and a sine at its own frequency
        and the product low-pass filtered, leaving that tone's slowly varying
        phasor. The ratio of the voltage and current phasors is Z(f,t).

        Parameters
        ----------
        n_periods : int
            Integrator length, in periods of ``base_frequency``. This is the
            time resolution: ``n_periods / base_frequency`` seconds.
        base_frequency : float, optional
            The frequency every tone is a harmonic of, in Hz. Defaults to the
            lowest excited frequency, which is correct for a multisine built
            on harmonics of ``1/Tp``. The integrator has to span whole periods
            of *this* frequency, not of the tone being demodulated, because
            that is what puts the other tones in its nulls.
        window : {'boxcar', 'hann'}
            ``'boxcar'`` nulls every harmonic exactly and is the default.
            ``'hann'`` rolls off faster but needs ``n_periods >= 2``.
        method : {'mix', 'ls'}
            ``'mix'`` demodulates and filters. ``'ls'`` fits a cosine, a sine,
            an offset and a local slope in a sliding window instead, which is
            insensitive to drift within the window but far slower.
        decimate : int, optional
            Report every n-th sample (``'mix'`` only). The result is smooth on
            the scale of the integrator, and the full-rate array is large.
        stride : int, optional
            Spacing of the reported instants for ``method='ls'``.

        Returns
        -------
        (impedance, time) : ndarray, ndarray
            ``impedance`` has shape ``(n_frequencies, n_instants)``.

        Notes
        -----
        A boxcar integrator spanning exactly one base period makes this
        identical to :meth:`run_stft_eis` with a one-period window -- verified
        to 1e-13 -- evaluated at every sample instead of once per window. Use
        :meth:`lia_valid_mask` to drop the instants whose window ran past the
        end of the record.
        """
        if base_frequency is None:
            base_frequency = float(np.min(self.frequencies))
        samples_window = integrator_length(
            self.sampling_time, base_frequency, n_periods, window)
        self.lia_samples_window = samples_window

        time = np.arange(self.voltage.size) * self.sampling_time
        fun = lia_impedance_ls if method == "ls" else lia_impedance_optim
        if method == "ls":
            columns, t_out = [], None
            for f in np.asarray(self.frequencies, dtype=float):
                Z_f, t_out = lia_impedance_ls(
                    time, self.voltage, self.current, self.sampling_time, f,
                    samples_window, stride=stride)
                columns.append(Z_f)
            return np.vstack(columns), t_out
        return lia_eis(time, self.voltage, self.current, self.sampling_time,
                       self.frequencies, samples_window,
                       impedance_calculation_fun=fun, window=window,
                       decimate=decimate)

    def lia_tone_rejection(self, n_periods=1, *, base_frequency=None,
                           window="boxcar"):
        """How far the lock-in integrator suppresses each other tone, in dB.

        After mixing at one frequency, every other tone of the multisine lands
        at the difference frequency. This reports the integrator's response
        there -- one row per demodulated tone. A boxcar over whole base
        periods nulls them all, so the numbers are limited only by arithmetic.
        """
        if base_frequency is None:
            base_frequency = float(np.min(self.frequencies))
        samples_window = integrator_length(
            self.sampling_time, base_frequency, n_periods, window)
        kernel = integrator_kernel(samples_window, window)
        return np.vstack([
            tone_rejection(kernel, self.sampling_time, self.frequencies, f)
            for f in self.frequencies])

    def lia_valid_mask(self, samples_window=None):
        """False where the lock-in integrator ran past the end of the record."""
        if samples_window is None:

            if samples_window is None:

                                 "samples_window explicitly")

                  band_halfwidth=None, rcond=None, noise=None, prune=True,

        ``detrend`` takes a strategy from :mod:`deistools.processing.detrending`,

        with an explanation.

        It is an argument here rather than state on the object on purpose. The
